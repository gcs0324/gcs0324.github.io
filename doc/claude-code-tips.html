01 常用指令
CLI 启动
claude启动交互式会话
claude -c继续上一次对话
claude -r恢复历史会话（弹出选择器）
claude -p "问题"非交互模式，输出后退出（适合管道）
claude --model sonnet指定模型（sonnet/opus/haiku）
claude --effort low思考深度（low/medium/high/max）
claude mcp管理 MCP Server
会话内 Slash 命令
/help查看帮助和可用命令
/model切换模型（sonnet/opus/haiku），不用重启
/effort切换思考深度（low/medium/high/max）
/cost查看当前会话 token 消耗和费用
/context查看当前上下文窗口使用情况
/clear清空上下文（重新开始，不退出会话）
/compact压缩对话历史，减少 token 占用
/memory编辑 CLAUDE.md 记忆文件
/config打开设置面板
/init为当前项目初始化 CLAUDE.md
/resume恢复之前的会话
/vim切换 vim 编辑模式
/diff查看最近代码变更的 diff
/agents管理后台代理
/remote-control开启远程控制（其他设备接管会话）
/bug向 Anthropic 报告 bug

02 开发类 Skills
Code — 编码工作流

写代码时自动触发。流程：读上下文 → 实现 → 跑 lint/typecheck → 验证。

brainstorming — 需求探索

创建功能前自动触发。Claude 先问需求、给方案，确认后再实现。不直接动手。

debug-pro — 调试协议

遇到 bug 时自动触发。7 步：复现 → 缩范围 → 定位 → 验证 → 修复 → 跑测试 → 预防。

writing-plans — 写实现计划

有需求时先写计划。每步精确到文件路径、代码、测试命令。确认后再执行。

executing-plans — 执行计划

有写好的计划时，按步骤执行，带 review 检查点。

security-auditor — 安全审查

涉及认证/加密/CORS/输入校验时触发。检查 OWASP Top 10、注入、XSS、密钥泄露。

git-essentials — Git 操作

需要 Git 操作时加载。分支管理、合并策略、rebase、冲突解决。

frontend-design — 前端设计

构建 UI 时触发。生成高质量前端代码，避免 AI 塑料感界面。

architecture-designer — 架构设计

设计系统/审查架构时触发。设计模式、ADR、可扩展性规划。

test-runner — 测试运行

需要跑测试时使用。自动检测框架，执行并分析结果。

memory — 持久化记忆

跨会话记忆。存储项目上下文、技术决策、偏好到文件，下次自动加载。

self-improving — 自我改进

Claude 自动评估工作质量，发现错误并永久改进。

caveman — 省 token 模式

说 "caveman mode" 触发。压缩语言回复，token 降 75%，准确度不变。

skill-creator — 创建 Skill

想自定义 skill 时使用。引导写 SKILL.md，定义角色、步骤、输出格式。

RTK — Rust Token Killer（CLI 代理）

不是 skill，是系统级 CLI 代理。通过 hook 自动重写命令，节省 60-90% token。对 Claude 透明，无需手动调用。

rtk gain查看 token 节省统计
rtk gain --history查看历史命令的节省量
rtk discover分析历史，找出没用 rtk 的命令
rtk proxy <cmd>原样执行命令（调试用）
原理：git status 原始输出可能几十行，rtk 重写后只保留关键信息，Claude 拿到的 token 少很多但信息量不变。
06 Compose 技能（编排模式）
什么是 Compose 技能

Compose 是 Claude Code 的编排模式，把多个 skill 组合成完整工作流。compose 技能不在普通 skill 列表里，只在 compose 模式下可用。

核心 Compose 技能
compose:brainstorm做任何创造性工作前必须先用。探索需求和设计。
compose:plan有规格说明时，先写实现计划再动手。
compose:debug遇到 bug 时使用。按调试协议排查。
compose:tdd先写测试再写实现。测试驱动开发。
compose:verify声称完成前必须验证。跑测试、lint，有证据才能说"搞定了"。
compose:review完成任务后审查。验证工作是否满足需求。
compose:merge实现+测试通过后，决定如何集成（merge/PR/cleanup）。
compose:parallel有 2+ 个独立任务时并行处理。
compose:execute有写好的计划时，按步骤执行带检查点。
compose:ask需要用户决策/确认时。驱动 question 工具。
compose:feedback收到代码审查反馈时使用。技术严谨地评估建议。
compose:subagent当前会话有独立子任务时派子代理执行。
典型 Compose 流程
# 新功能开发
brainstorm → plan → tdd → implement → verify → merge

# 修 Bug
debug → implement → verify

# 代码审查
review → feedback → implement
07 实用技巧
CLAUDE.md 配置

项目根目录放 CLAUDE.md，写上项目架构、构建命令、编码规范。每次启动自动加载，不用重复解释。

# CLAUDE.md 示例
## Commands
- 构建：mvn clean package
- 测试：mvn test
- Lint：mvn spotless:check

## Conventions
- 用 SLF4J 日志，不用 System.out
- Controller 不写业务逻辑
- Service 层做参数校验
先 Read 再 Edit

Claude Code 每次编辑都基于 Read 获取的真实内容。先 Read → 理解上下文 → 再 Edit。不 Read 直接 Edit 大概率失败。

Grep 定位再精确读

找代码时先 Grep 定位行号，再 Read 那几行。不要一上来就读整个大文件。

小步迭代

一次 Edit 改一小段。一次改整个文件容易出错，且失败后 oldString 匹配不上要重来。

及时开新会话

对话超过 30 轮后上下文膨胀。/clear 清空上下文，或开新会话（claude -c 继续）。用 CLAUDE.md 和 memory 恢复上下文。

用 /cost 监控消耗

定期跑 /cost 看 token 消耗。发现异常高时用 /compact 压缩或 /clear 重开。

08 成本控制
省钱策略
用 Sonnet 不用 Opus80% 任务 Sonnet 够用。复杂推理才切 Opus。/model 随时切。
精确读取Read(offset=100, limit=50) 只读 50 行，省 90% token。
Grep 先行先 Grep 找行号再 Read，比全量读省很多。
/compact 压缩对话变长时压缩历史，减少每次请求的 token。
caveman 模式说 "caveman mode"，压缩语言，token 降 75%。
/effort low简单任务用低思考深度，减少推理 token。
rtk（自动）RTK 通过 hook 自动重写命令输出，节省 60-90% token，无需手动操作。
及时 /clear30 轮后清空重开，比继续长对话更省。
Token 消耗参考
操作估算 Token
读 100 行文件~800
读 500 行文件~4000
一次 Edit~500
子代理搜索~2000
一次完整对话（10轮）~8000-15000
