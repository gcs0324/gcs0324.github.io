§1 C/S 与 P2P 模型

客户/服务器 B 会辨析

服务器通常持续运行、有固定可达地址；客户主动发起请求，客户之间不直接通信。Web、FTP、邮件服务属于典型 C/S。

P2P B 会辨析

节点既可请求也可提供服务，扩展性强，但节点上线时间和地址不稳定，管理、安全与内容发现更复杂。P2P 不表示完全没有协调服务器。

§2 DNS 域名系统 A 必学

DNS 是分布式、层次化的命名系统，把域名映射为 IP，也能保存别名、邮件服务器等记录。根服务器不是保存全世界每个域名的最终地址，而是告诉查询者下一层该问谁。

服务器负责什么
根域名服务器指向顶级域服务器
顶级域服务器管理 .com、.cn 等顶级域下的委派
权威域名服务器保存其负责区域的最终记录
本地域名服务器替主机查询并缓存结果，不属于域名层次树的固定一级
教程例题 · 递归查询与迭代查询
主机要解析 www.example.com，本机和本地 DNS 均无缓存。典型查询过程是什么？
1主机把请求交给本地 DNS，并希望它直接返回最终结果。这一段通常是递归查询：主机不想自己继续问别的服务器。
2本地 DNS 问根服务器；根不替它查到底，而是返回 .com 顶级域服务器地址。这是迭代响应：“我不知道最终答案，但你可以问它”。
3本地 DNS 再问 .com，得到 example.com 权威服务器地址；再问权威服务器，获得 www 的 IP。
4本地 DNS 把 IP 返回主机，并按 TTL 缓存。下一次相同查询可直接命中缓存，减少时延和上级服务器压力。
主机→本地 DNS 常为递归；本地 DNS→根/TLD/权威常为迭代。考试以题图箭头和题设为准
易错

DNS 常用 UDP 53，但不是“只能 UDP”：区域传送通常用 TCP，响应过大或被截断也可能转 TCP。不要把常见实现写成绝对规则。

§3 FTP 文件传输 B 会辨析

控制连接

客户端连接服务器 TCP 21 端口，发送登录、切换目录、下载等命令。控制连接在整个会话中保持。

数据连接

真正传文件或目录列表时另建 TCP 连接。主动模式服务器常从 20 端口连客户端；被动模式由客户端连接服务器协商出的端口。

短场景 · 为什么控制与数据分离
下载大文件时，用户为什么仍能通过控制连接发送取消命令？
1文件字节走数据连接；命令和响应走独立控制连接，不会排在大文件字节流之后。
2因此一个 FTP 会话至少涉及控制与数据两类连接。“FTP 使用两条连接”是逻辑角色，传多个文件时数据连接可能反复建立。
分离后控制命令不会被大文件传输阻塞
§4 电子邮件协议
协议方向传输层与常用端口核心特点
SMTP客户端→发送服务器；服务器→服务器TCP 25（考试常用）负责“推送/发送”，基本协议偏 7 位 ASCII，MIME 扩展附件
POP3接收服务器→用户代理TCP 110偏下载到本地，可设置保留服务器副本
IMAP用户远程管理服务器邮箱TCP 143文件夹和状态保留在服务器，适合多设备同步
HTTP浏览器访问 Web 邮箱通常 TCP 80/443浏览器与邮件网站之间用；邮件服务器之间仍可用 SMTP
记忆

SMTP 管发，POP3/IMAP 管收。SMTP 是推协议；POP3/IMAP 是用户主动拉取/访问邮箱。Web 邮箱页面使用 HTTP 不会替代后台邮件服务器间的 SMTP。

§5 HTTP 与万维网

无状态 B 会辨析

服务器默认不记得两次请求来自同一业务会话。Cookie 把标识保存在客户端并随请求发送，服务器再结合会话数据识别用户。无状态不等于底层不能使用持续 TCP 连接。

连接方式 A 必学

非持续 HTTP 每个对象单独建 TCP；持续 HTTP 可在同一连接上传多个对象。HTTP/1.1 默认持续连接；是否流水线、并发数和对象传输时间以题设为准。

状态码类别含义代表
1xx信息性100 Continue
2xx成功200 OK
3xx重定向/缓存相关301、304
4xx客户端请求问题400、404
5xx服务器处理失败500、503
教程例题 · HTTP 的 RTT 计算
DNS 已完成，忽略对象发送时间。页面含 1 个 HTML 和 3 张小图，客户端与服务器 RTT=40 ms。比较非持续串行、非持续并行（3 图同时）和持续非流水线。
1每次新 TCP 连接先用 1 RTT 握手，再用 1 RTT 发 HTTP 请求并收到首字节，所以一个小对象若单独连接，控制时延是 2 RTT。
2非持续串行：HTML 2 RTT，三图各 2 RTT，共 8 RTT=320 ms。
3非持续并行：先取 HTML 用 2 RTT；知道图片 URL 后，三条连接同时进行，各 2 RTT但彼此重叠，所以再加 2 RTT，共 4 RTT=160 ms。
4持续非流水线：只建立一次 TCP。HTML 用握手 1 RTT + 请求 1 RTT；随后三图在同一连接上逐个请求，每个 1 RTT，共 5 RTT=200 ms。
串行非持续 320 ms；并行非持续 160 ms；持续非流水线 200 ms。若题设允许流水线，三图请求可再重叠
§6 输入 URL 后发生什么
教程例题 · 把 DNS 和 HTTP 时延串起来
本地 DNS 无缓存，依次联系根、顶级域、权威服务器，三个 DNS 往返各 20 ms；浏览器到 Web 服务器 RTT=50 ms。采用一条持续 TCP 获取单个 HTML，忽略发送时间与 TLS，最少多久收到首字节？
1DNS 三次迭代往返依次发生，不能并行：3×20=60 ms。主机到本地 DNS 的额外 RTT 若题目给出，还应加上。
2得到 IP 后，TCP 三次握手到可发送普通 HTTP 请求按经典模型计 1 RTT=50 ms。
3HTTP 请求发出到响应首字节返回再计 1 RTT=50 ms。
最少 60+50+50=160 ms；不能漏掉 DNS，也不能把三次握手误算成 3 RTT
§7 速记、易错与练习

应用层拿分清单

  • DNS：主机问本地常递归，本地向层次服务器常迭代；缓存受 TTL 控制。
  • FTP：控制 TCP 21，数据另建连接；主动/被动方向不同。
  • SMTP 发，POP3/IMAP 收；Web 邮箱页面走 HTTP。
  • HTTP 无状态不等于 TCP 非持续；Cookie 用于识别状态。
  • 非持续单对象经典控制时延 2 RTT；持续连接省去重复握手。
  • 端口号是常见值，不要把 DNS/HTTP 的传输层选择写成永远不变。
考试型练习 · 协议分层判断
用户在浏览器打开 Web 邮箱并给另一域用户发信，浏览器、发送方邮件服务器、接收方邮件服务器之间分别主要使用什么协议？
1浏览器与 Web 邮箱服务器之间是网页交互，使用 HTTP/HTTPS。
2发送方邮件服务器把邮件推给接收方邮件服务器，使用 SMTP。
3接收者若用专用客户端同步邮箱，常用 POP3 或 IMAP；若仍用浏览器，则浏览器这一段仍是 HTTP/HTTPS。
浏览器↔网站：HTTP(S)；邮件服务器↔邮件服务器：SMTP；专用收信客户端：POP3/IMAP
