§1 OS 是资源管理者，也是用户与硬件之间的接口

为什么需要 OS

CPU、内存、文件和外设都可能被多个程序竞争。OS 统一分配和保护这些资源，并用“进程、虚拟内存、文件”等抽象隐藏硬件细节。

四个基本特征

  • 并发：多个事件在一段时间内交替推进。
  • 共享：多个进程共同使用资源。
  • 虚拟：把物理资源抽象成更多或更易用的逻辑资源。
  • 异步：进程以不可预知速度向前推进。
易错

并发是一段时间内同时存在，单核上可以交替执行；并行是同一时刻确实在多个处理单元上执行。

§2 用户态与内核态

用户态

普通应用程序执行在低特权级，不能直接执行修改中断屏蔽、设置时钟、访问 I/O 端口等特权指令。这是为了防止一个应用损坏整个系统。

内核态

OS 内核执行在高特权级，可访问受保护资源和执行特权指令。用户程序需要内核服务时，必须通过系统调用进入内核。

教程例题 · 判断“进入内核”和“切换进程”
进程 P 执行 getpid()、读磁盘文件和发生时钟中断时，哪些会进入内核？哪些必然切换进程？
1getpid() 是系统调用，会从用户态陷入内核。它通常能快速返回，因此不必然切换到其他进程。
2读文件也是系统调用。若数据已在页缓存，可以直接复制并返回；若需要等磁盘，P 会阻塞，调度器才切换其他进程。
3时钟中断会异步进入内核。内核更新时间和调度信息；若时间片未用完，可返回 P，所以也不必然切换进程。
三种情况都可进入内核；没有一种仅凭题干就必然切换进程。判断切换要看是否阻塞或触发调度。
§3 中断、异常与系统调用
类型来源是否与当前指令相关例子关键判断
外中断CPU 外部通常异步时钟、I/O 完成当前指令执行完后响应
故障 Fault当前指令同步缺页、保护错误处理后可能重新执行该指令
自陷 Trap程序主动执行同步系统调用指令有意识请求内核服务
终止 Abort严重错误同步硬件故障通常无法返回原指令

典型响应主线

CPU 在可中断点检测请求 → 保存断点和程序状态 → 转内核态 → 根据中断向量找处理程序 → 执行服务 → 恢复现场 → 返回原程序或经调度运行另一进程。

易错

缺页异常不是 I/O 外中断。访存指令发现页不在内存是同步故障；之后磁盘把页读入完成，才以I/O 外中断通知 CPU。

§4 从可执行文件到进程内存映像

链接

把多个目标模块与库合并，解决外部符号地址。动态链接可在装入或运行时再关联共享库。

装入

装入器建立程序的虚拟地址空间和初始映射。不要把“装入到虚拟地址空间”误写成“全部页立即读入物理内存”。

运行时映像

代码段、全局数据、堆和栈位于同一进程的虚拟地址空间；它们的增长方向与具体边界以题设为准。

§5 结构、引导与虚拟机
结构核心思路优点代价/常见考法
宏内核多数服务运行在内核空间直接调用，性能高内核大，一个模块故障影响范围大
微内核内核只保留最基本机制，服务移到用户态隔离好、易扩展跨边界消息传递和状态切换带来开销
分层/模块化按功能分层或通过明确接口装配易理解、测试和替换分层边界可能限制灵活性

引导主线 C

固件执行 → 定位引导程序 → 把 OS 内核装入内存 → 跳转内核入口 → 初始化硬件和核心子系统 → 启动首个用户空间进程。

虚拟机 C

第一类监控器直接在硬件上；第二类运行在宿主 OS 上。110 分目标会辨析即可，不学产品配置和虚拟化扩展细节。

§6 速记、易错与考试型练习

拿分清单

  • 系统调用是用户程序主动请求内核服务的接口。
  • 用户态→内核态不等于一定进程切换。
  • 缺页是同步异常；页读入完成是 I/O 中断。
  • 特权指令只能在内核态执行。
  • 微内核隔离好，但消息传递和状态切换有开销。

时间紧可跳

  • 操作系统世代的具体年份和机型。
  • 外核的实现细节。
  • 具体虚拟化产品、容器运行时参数。
  • 某个 OS 的完整开机日志。
考试型练习 · 事件归类
将“时钟到期、执行非法指令、调用 write()、访问尚未调入的合法页面”分类。
1时钟到期由 CPU 外部的定时器产生，是异步外中断。
2非法指令是当前指令导致的同步异常，通常无法靠重执行原指令恢复。
3write() 由程序主动调用，是系统调用/自陷。
4合法页不在内存是缺页故障；页调入后可重新执行原访存指令。
外中断 / 同步异常 / 系统调用 / 可恢复缺页故障。
