01 MCP 是什么
一句话定义

MCP（Model Context Protocol）是 Anthropic 提出的"模型与工具之间的开放协议"，让 Claude / Cursor / Codex 等 AI 客户端通过一个统一的协议调用外部能力：查代码、爬网页、操作浏览器、查数据库……

对你而言：MCP server 就是一个"插件"。装上它，Claude Code 多出一组新工具。

MCP server 和 Skill 的区别
维度MCP serverClaude Skill
类型常驻进程Markdown 文件 + 可选脚本
提供什么工具（tool calls）提示词 + 标准动作流程
装在哪~/.claude.json 的 mcpServers~/.claude/skills/ 目录
有了对方还需要吗需要（核心能力）需要（怎么用工具的经验包）
典型例子codegraph / playwright-mcp / tavilyai-briefing / pdf / xlsx
结论：两者互补，不互相替代。MCP 提供工具，Skill 提供怎么用工具的最佳实践。

03 三种安装方式对比
npm 全局 vs npx 缓存 vs Docker
方式包放哪首次启动升级方式可见性
npm i -g/usr/local/lib/node_modules/快npm update -g 主动✅ npm ls -g
npx -y @latest~/.npm/_npx/<hash>/慢 2-5s（拉包）每次启动可能被动升级❌ npm 看不见
docker runDocker 镜像极慢（拉镜像）手动 docker pull✅ docker images

★ npm 全局（本机选定）

装一次长期存在，升级时机自己控制，npm ls -g --depth=0 一行盘点全部 MCP。适合长期主力使用。

npx -y <pkg>

无需安装，每次启动从缓存找；首次延迟明显。适合一次性试用，不适合生产。

关键提醒：npx 安装的 MCP npm ls -g 看不见，得去 ~/.npm/_npx/ 翻。混用就破坏"统一可见"。
04 日常管理命令
查看 / 盘点
claude mcp list查看所有已注册的 MCP（含连接状态 ✓/✗）
npm ls -g --depth=0查看所有 npm 全局包（MCP 包都在这）
ls ~/.npm/_npx/查看 npx 缓存目录（每个 hash 是一个包）
cat ~/.claude.json | jq .mcpServers直接看 MCP 配置原文
添加 / 删除
npm i -g <pkg>先全局装 npm 包
claude mcp add <name> -s user -- <binary>注册到 Claude Code（-s user 表示对所有项目生效）
claude mcp add <name> -s user -e KEY=val -- <binary>注册时同时传入环境变量（API Key 等）
claude mcp remove <name>从 Claude Code 注册表移除（不卸载包）
npm un -g <pkg>卸载 npm 包
升级 / 清理
npm update -g <pkg>升级单个全局包
npm update -g升级所有全局包（包括 MCP）
npm cache clean --force清 npm 缓存（不删全局包）
rm -rf ~/.npm/_npx清 npx 缓存（下次 npx 自动重建）
-s 参数：user = 当前用户全部项目可用；project = 仅当前项目；local = 默认（本项目）。长期 MCP 一律 -s user。
05 为什么统一到"npm 全局 + 裸 binary"
这条路线的三个收益
  • ①可见：npm ls -g --depth=0 一行看全所有 MCP，无需进 ~/.npm/_npx/ 挨个翻 hash 目录
  • ②可控：升级时机自己决定，不会因 @latest 被动引入 breaking change
  • ③无启动延迟：裸 binary 直接执行，npx 那 2-5s 的"查仓库"开销消失
代价
  • ·升级要主动跑 npm update -g <pkg>，不像 npx 自动跟最新
  • ·非 Node 写的 MCP（如 Rust 写的 codegraph）走自己的安装渠道，无法塞进 npm 体系——这是协议开放的代价，不可避免
06 Smithery 评估（暂未采用）
Smithery 是什么

Smithery 是 MCP 生态的注册表 + 安装器（类似 brew、apt），通过 smithery.ai 浏览所有公开 MCP，用 CLI 一行命令装到任意客户端：

npx -y @smithery/cli@latest install <server> --client claude

它的真正价值不在"少打一条命令"，而在跨客户端同步——同一个 MCP 装到 Claude Code / Cursor / Claude Desktop，命令一致，省心。

为什么本机没用
核心 MCPSmithery 注册表有吗
@colbymchenry/codegraph❌ 没有（只能找到 project-mapper 等替代品）
@playwright/mcp（微软官方）❌ 没有（出来的全是周边）
结论：Smithery 是社区注册中心，MCP 作者要主动提交才出现。微软、个人作者很多都没提交。强行切到 Smithery = 本机两个主力 MCP 还得手动管，Smithery 只能管"未来新装的"，反而破坏统一性。
什么时候值得切到 Smithery
  • ·开始用 ≥ 2 个客户端（Claude Code + Cursor + Claude Desktop 等）共享一批 MCP
  • ·MCP 数量推到 10+，手动维护成本明显
  • ·经常试新 MCP，想用 Smithery 的搜索 / 评分功能
  • ·想用 Smithery 托管模式（远程 HTTP，本地零依赖）
07 踩过的坑
坑 1：装了 npm 包但 Claude Code 不认识

现象：npm i -g xmind-generator-mcp 之后 claude mcp list 看不到它。

原因：npm 装包 ≠ 注册到 Claude Code。两步缺一不可。

解决：装完包必须再跑一次 claude mcp add <name> -s user -- <binary>。

坑 2：npx 缓存看不见

现象：用 npx @playwright/mcp@latest 启动后，npm ls -g 找不到它。

原因：npx 把包放在 ~/.npm/_npx/<hash>/，不是 /usr/local/lib/node_modules/，npm 不管。

解决：如果想"统一可见"，改走 npm i -g，配置里写裸 binary 名。

坑 3：换 MCP 包名后旧缓存残留

现象：codegraph 从老包名换到 @colbymchenry/codegraph，~/.npm/_npx/ 里仍存着一份旧版。

解决：定期 rm -rf ~/.npm/_npx/<hash> 清理；或一次性 rm -rf ~/.npm/_npx 全清，下次 npx 自动重建。

坑 4：把 Smithery 当包管理器

误区：以为 Smithery 是 brew、能管所有 MCP。

真相：Smithery 是社区注册中心，作者没提交 = 搜不到。覆盖率约等于 npm 上 MCP 的子集。

08 加一个新 MCP 的标准流程
三步走（以 Tavily 为例）
# 1. 全局安装 npm 包
npm i -g tavily-mcp

# 2. 注册到 Claude Code（带 API Key）
claude mcp add tavily -s user -e TAVILY_API_KEY=tvly-xxx -- tavily-mcp

# 3. 验证
claude mcp list
# → tavily: tavily-mcp - ✓ Connected
非 Node 写的 MCP 怎么办
语言典型安装方式例
Rust下载 binary / cargo installcodegraph（本机现状）
Pythonpipx install / uvxgit-mcp-server / sequential-thinking
GoGitHub Release 下 binary少数官方 MCP
"100% 单一安装方式"做不到，因为 MCP 是开放协议，社区什么语言都写。最现实策略：Node 系全 npm 全局，Python 系全 uvx，剩余个别走自己的渠道——每"类语言"内部统一即可。
日常维护节奏建议
  • ·每周：claude mcp list 看一下连接状态，有 ✗ 的排查
  • ·每月：npm outdated -g 看哪些 MCP 有新版，按需 npm update -g <pkg>
  • ·每季：rm -rf ~/.npm/_npx 清 npx 缓存（如果用过 npx 试包）
  • ·装新 MCP 前：先 npm view <pkg> 看一眼维护情况、最新版本，避免装到僵尸包
