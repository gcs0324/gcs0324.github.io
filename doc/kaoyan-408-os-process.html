§1 进程、PCB 与线程

程序

存放在外存上的静态指令和数据集合。同一程序可同时启动多个进程。

进程

程序的一次执行过程，是资源分配的基本单位。进程实体由程序段、数据段和 PCB 等组成。

线程

CPU 调度的基本单位。同进程线程共享地址空间和打开文件，但各自有程序计数器、寄存器和栈。

线程模型谁看得见线程一个线程阻塞多核并行切换开销
用户级线程线程库，内核只看到进程若内核只对整个进程调度，可导致整个进程阻塞多对一模型不能低，可不进内核
内核级线程OS 内核只阻塞该线程可以较高，需内核参与
§2 状态转换必须由“事件”驱动

创建、终止、阻塞、唤醒

这些是进程控制原语，执行时要修改 PCB 和队列，所以必须在内核态完成。

挂起不等于阻塞

阻塞是等事件；挂起是把进程映像部分换出内存。因此可以有“静止就绪”和“静止阻塞”。

方式数据如何传同步责任典型特点

§4 调度指标的起止点
周转时间 = 完成时刻 - 到达时刻　　带权周转时间 = 周转时间 ÷ 服务时间
响应时间 = 首次获得 CPU 时刻 - 到达时刻　　等待时间 = 在就绪队列中等待的总时间
易错

服务时间是进程真正占用 CPU 的时间；若题目包含 I/O，不能一律用“周转-服务”代替就绪等待，因为阻塞等 I/O 不属于就绪等待。

算法选择依据是否抢占优点典型问题
FCFS按到达顺序非抢占简单、公平护航效应，短作业等长作业
SJF就绪中服务时间最短非抢占给定条件下平均等待时间小长作业可能饥饿，实际时长难预知

教程例题 · SRTF 为什么在新进程到达时重新比较
进程 P1/P2/P3 到达时刻分别为 0/1/2，CPU 服务时间为 7/4/1。采用 SRTF，忽略切换开销，画 Gantt 图并计算周转时间。
1t=0 只有 P1，所以运行 P1。到 t=1 时 P1 已运行 1，剩余 6。
2t=1 新到 P2，P2 需 4，小于 P1 剩余 6，因此 P2 抢占。不是比较 P1 原始的 7，而是比较当前剩余时间。
3t=2 新到 P3。此时 P2 剩余 3，P1 剩余 6，P3 需 1，因此改运行 P3，t=3 完成。
4t=3 只剩 P2(3) 和 P1(6)，先运行 P2 到 t=6，再运行 P1 到 t=12。
P10→1
P21→2
P32→3
P23→6
P16→12
5完成时刻 P1=12、P2=6、P3=3。周转：P1=12-0=12，P2=6-1=5，P3=3-2=1。平均周转=(12+5+1)/3=6。
Gantt：P1[0,1) → P2[1,2) → P3[2,3) → P2[3,6) → P1[6,12)；平均周转 6。检查：总 CPU 时间 7+4+1=12，与结束时刻一致。
教程例题 · RR 时间片结束时新进程怎么入队
P1 在 t=0 到达，需 5；P2 在 t=1 到达，需 3；时间片 q=2。约定在时间片结束时，先把该时刻到达的新进程入队，再把未完成的当前进程放队尾。
1P1 运行 [0,2)，剩余 3。P2 在 t=1 已进就绪队列，t=2 时队列为 P2，再把 P1 放到后面：P2,P1。
2P2 运行 [2,4)，剩余 1，放到 P1 后，队列 P1,P2。
3P1 运行 [4,6)，剩余 1；P2 运行 [6,7) 完成；P1 运行 [7,8) 完成。
P1[0,2) → P2[2,4) → P1[4,6) → P2[6,7) → P1[7,8)。题目若给了“同时到达/重入队顺序”，必须照题设，不能自己猜。
§6 易错清单与考试型练习

拿分清单

  • 阻塞→就绪，不能直接阻塞→运行。
  • 进程是资源分配单位，线程是 CPU 调度单位。
  • SRTF 比剩余时间，新进程到达时重新调度。
  • RR 的同时事件顺序以题设为准。
  • 响应时间到首次获得 CPU 结束，不是到完成。

C 类不深挖

  • Linux CFS 红黑树实现。
  • NUMA 复杂负载均衡参数。
  • 具体线程库 API 全集。
  • 实时调度的工业级可调度性证明。
考试型练习 · 优先级调度的数据结构
高优先级进程在就绪队列队首，采用单链表保存。若希望调度时 O(1) 取队首，新进程按优先级插入，主要开销在哪里？
1调度时直接删除队首，已知头指针，时间 O(1)。
2插入时为保持优先级有序，单链表需要从头扫描定位，最坏 O(n)。
取最高优先级 O(1)，有序插入最坏 O(n)。数据结构决定的是调度实现开销，不改变调度策略本身。
