01 · String 字符串
STR
String
二进制安全 · 最大 512 MB · 最基础类型
int
embstr
raw (SDS)
底层实现

Redis String 底层统一用 SDS（Simple Dynamic String） 存储，按值内容选择三种编码：

int值为 long 范围内的整数，直接把指针位存整数值，零内存分配，INCR/DECR 直接对整数操作，无需解析字符串。
embstr值 ≤ 44 字节，redisObject 头与 SDS 一次性分配在连续内存，只需一次 malloc，CPU 缓存友好。字符串只读——修改时直接转 raw。
raw值 > 44 字节，redisObject 与 SDS 分开分配。SDS 头记录 len / alloc，O(1) 取长度，预分配空间避免频繁 realloc。
常用命令
SET key value [EX seconds] [NX] [XX]
设置值。NX=不存在才写（分布式锁），XX=存在才写，EX 同时设过期秒数，原子操作。
GET key  /  MGET k1 k2 ...
获取单个/多个值，不存在返回 nil。MGET 减少网络 RTT。
INCR key  /  INCRBY key delta
原子自增。key 不存在从 0 开始。计数器、限流、全局 ID 生成。
SETNX key value
key 不存在才设置。分布式锁原语，建议用 SET NX EX 替代（原子性更好）。
EXPIRE key seconds  /  TTL key
设置 / 查询过期时间。TTL 返回 -1=永久，-2=不存在。
APPEND key value
追加内容，返回新长度。日志追加、时序数据拼接。
对象缓存（JSON 序列化存储） 计数器（PV / 点赞） 分布式锁（SET NX EX） Session 存储 接口限流（INCR + EXPIRE） 全局唯一 ID（INCR）
02 · List 列表
LST
List
有序 · 可重复 · 双端操作 · 支持阻塞消费
listpack（小规模）
quicklist（大规模）
底层实现

listpack：元素少时使用。每个 entry 紧凑排列，自包含长度字段，无前驱指针（解决 ziplist 的连锁更新问题）。顺序遍历快，内存紧凑。

quicklist：元素超阈值后转换。本质是 双向链表 + listpack 的组合——链表每个节点是一个 listpack 页（默认最多 128 个元素），兼顾内存连续性与头尾 O(1) 操作。

LPUSH头节点 listpack 未满 → 直接头插；已满 → 新建 listpack 节点链到链表头部。
LRANGE从头节点开始，跨 listpack 页顺序遍历，收集范围内元素。O(S+N)，S 为起始偏移。
BLPOP列表为空时，客户端连接加入等待队列；有新元素 PUSH 时服务端主动通知，无需轮询。
常用命令
LPUSH key v1 v2  /  RPUSH key v
从左/右插入。LPUSH 多个值时最后一个最靠近头部。
LPOP key [count]  /  RPOP key
弹出头/尾元素。Redis 6.2+ 支持 count 参数一次弹出多个。
LRANGE key start stop
范围查询，下标从 0 开始，-1 表示最后一个。LRANGE key 0 -1 取全部。
BLPOP key [key...] timeout
阻塞弹出。列表为空时等待，有元素立即返回。timeout=0 永久等待。消息队列核心命令。
LTRIM key start stop
截断列表，只保留 [start, stop] 范围。与 LPUSH 组合实现固定长度队列（最近 N 条）。
LLEN key
获取列表长度，O(1)。
消息队列（LPUSH + BRPOP） 最近浏览记录（LPUSH + LTRIM） 时间线 栈（LPUSH + LPOP） 队列（RPUSH + LPOP）
03 · Hash 哈希
HSH
Hash
field-value 映射 · 适合存储对象字段
listpack（字段少）
hashtable（字段多）
底层实现

listpack：字段数 ≤ 128 且每个值 ≤ 64 字节时使用。field 和 value 交替紧凑排列（field₁ value₁ field₂ value₂…），遍历时逐项比较 field，内存占用极小。

hashtable（dict）：超过阈值后转为 Redis 内部 dict 结构——两张哈希表（ht[0] / ht[1]）用于渐进式 rehash。MurmurHash2 计算 field 哈希，开链法解决冲突，查找均摊 O(1)。扩容时双表并存，每次读写顺带迁移少量桶，不阻塞服务。

HSET计算 field 哈希 → 定位桶 → 链表头插。负载因子 >1 触发 rehash 扩容。
HGET哈希定位桶 → 遍历链表比较 field → 返回 value。均摊 O(1)。
常用命令
HSET key field value [field value ...]
设置一个或多个字段。Redis 4.0+ HSET 支持批量写入。
HGET key field  /  HMGET key f1 f2
获取单个 / 多个字段。O(1) / O(N)。
HGETALL key
返回所有 field-value 对。字段多时用 HSCAN 代替，避免阻塞。
HINCRBY key field delta
对指定字段原子自增。购物车数量、计数字段。
HDEL key field [field ...]
删除一个或多个字段，返回实际删除数。
HEXISTS key field
判断字段是否存在，返回 0/1。
用户信息缓存（uid → {name, age, city}） 购物车（uid → {goodsId: count}） 商品详情字段缓存 配置项存储
04 · Set 集合
SET
Set
无序 · 不重复 · 支持交并差集运算
intset（纯整数小集合）
listpack（混合小集合）
hashtable（大集合）
底层实现

intset：所有元素为整数且数量 ≤ 512 时使用。本质是有序整数数组，升序排列，插入/查找用二分查找 O(log N)，内存连续极省空间。插入非整数立刻整体升级为 hashtable。

listpack：混合类型且元素少时（Redis 7.2 引入路径），紧凑连续存储。

hashtable：大集合时，dict 的 value 统一为 NULL，只用 key 存成员，去重由哈希表天然保证。集合运算（SINTER / SUNION / SDIFF）通过遍历哈希表实现，O(N)。

常用命令
SADD key member [member ...]
添加元素，重复自动忽略，返回实际新增数量。
SISMEMBER key member
判断成员是否存在，O(1)。Redis 6.2+ 支持 SMISMEMBER 批量判断。
SINTER k1 k2  /  SUNION  /  SDIFF
交集 / 并集 / 差集。加 STORE 后缀将结果写入新 key。求共同关注用 SINTER。
SRANDMEMBER key count
随机返回 count 个元素，不删除。正数不重复，负数允许重复。抽奖摇号。
SPOP key [count]
随机弹出并删除元素。一次性不可重复抽奖。
SMEMBERS key
返回所有元素。大集合用 SSCAN 迭代，避免阻塞。
标签系统 共同关注 / 好友（SINTER） 去重 UV（小规模） 抽奖（SRANDMEMBER / SPOP） 黑白名单
05 · Sorted Set 有序集合
ZST
Sorted Set
元素绑定浮点 score · 自动排序 · 元素不重复
listpack（小规模）
skiplist + hashtable（大规模）
底层实现

listpack：元素 ≤ 128 且每个值 ≤ 64 字节时，member 和 score 交替紧凑存储并按 score 有序排列。小数据下遍历比跳表更快（CPU 缓存命中率高）。

skiplist + hashtable 双索引：超过阈值后，同时维护两个结构：

skiplist多层有序链表，节点随机晋升（概率 25%，上限 32 层）。按 score 排序，范围查询 O(log N)，是 ZRANGE / ZRANGEBYSCORE 的基础。
hashtablemember → score 的哈希映射，O(1) 查单个元素 score，是 ZSCORE / ZRANK 的基础。
共享内存两个结构共享 member 字符串指针，不双倍存储字符串内容，只多一个指针和 score 的开销。
ZADD同时更新 skiplist（重新定位节点）和 hashtable（更新 score），写放大换查询速度。
常用命令
ZADD key [NX|XX] [GT|LT] score member
添加元素。GT=新 score 更大才更新（排行榜），LT=更小才更新（延迟队列）。
ZRANGE key min max [BYSCORE] [REV] [LIMIT offset count]
Redis 6.2+ 统一范围查询命令。可按排名或 score 正/逆序，支持分页。
ZRANK key member [WITHSCORE]
查询排名（从 0 开始）。ZREVRANK 为逆序排名。O(log N)。
ZSCORE key member
O(1) 获取 score，依赖内部 hashtable。
ZINCRBY key delta member
原子增减 score 并同步更新 skiplist 位置。排行榜加分场景。
ZRANGEBYSCORE key min max [LIMIT offset count]
延迟队列取到期任务：ZRANGEBYSCORE key 0 now LIMIT 0 N
排行榜（score=分数） 延迟队列（score=执行时间戳） 滑动窗口限流（score=时间戳） 热搜榜 带权重任务调度
扩展类型 Extended Types
BIT
Bitmap 位图
本质是 String · 按位寻址 · 2 亿用户签到仅需 25 MB
底层实现

Bitmap 底层就是 String（SDS），没有独立数据结构。Redis 把 SDS 的每个字节拆成 8 个 bit，通过 offset 定位到具体 bit 读写。最大 offset 为 2³²-1，约 512 MB = 40 亿个 bit。

BITCOUNT 用查表法（byte → popcount 预计算表）优化统计，比逐位遍历快得多。BITOP 在字节层面逐字节 AND / OR / XOR，O(N) 线性遍历。

常用命令
SETBIT key offset value
设置偏移量 offset 的 bit 为 0/1。offset 不连续时中间自动填 0。
GETBIT key offset
获取指定 offset 的 bit 值，O(1)。
BITCOUNT key [start end]
统计值为 1 的 bit 数量，可指定字节范围。月签到统计。
BITOP AND|OR|XOR|NOT destkey k1 k2
多 Bitmap 位运算，结果存入 destkey。BITOP AND 求连续签到用户。
用户签到打卡（offset=userId，key=日期） 用户在线状态 布隆过滤器底层 连续登录统计（BITOP AND）
HLL
HyperLogLog
概率基数统计 · 误差 ≈ 0.81% · 固定 12 KB
底层实现

存储在 String 中，按算法格式编码，不是普通文本。将元素哈希后统计二进制串中前导零最大长度 k，用 2^k 估算基数。Redis 用 16384 个桶分桶计算，调和平均后误差约 0.81%。

无论加多少元素最多占 12 KB（密集模式），元素少时用稀疏编码只占几百字节。不能获取具体元素，也不支持删除。

常用命令
PFADD key element [element ...]
添加元素。内部估算更新返回 1，否则 0。
PFCOUNT key [key ...]
返回基数估算值。多个 key 时返回并集估算。
PFMERGE destkey key1 key2
合并多个 HLL，适合多端数据汇总统计 UV。
UV 统计（千万级用户去重） 独立 IP 计数 搜索词去重计数
GEO
Geo 地理位置
底层复用 Sorted Set · score = GeoHash 编码
底层实现

没有独立数据结构，底层复用 Sorted Set。将经纬度用 GeoHash 算法编码为 52 位整数作为 score，member 存地点名称。GeoHash 把地球网格化，经纬度交错编码成 Z 形曲线，相邻网格编码相邻，按 score 范围查询 = 空间区域查询。

GEOSEARCH 半径查询时，先把圆形近似为外接正方形换算为 score 范围，用 skiplist 范围查询，再过滤掉超出圆形的点。精度约 0.6 mm。

常用命令
GEOADD key lng lat member [...]
批量添加地理位置，内部调用 ZADD。
GEODIST key m1 m2 [m|km|mi|ft]
计算两点距离，指定单位。
GEOSEARCH key FROMMEMBER m BYRADIUS r km ASC
Redis 6.2+，以某成员为圆心搜索周围点，ASC 排序，COUNT 限制返回数量。附近的人核心命令。
GEOPOS key member [member ...]
返回经纬度坐标，从 score 逆向解码 GeoHash。
附近的人 / 门店（GEOSEARCH） 配送距离计算 骑手实时位置
STM
Stream 流
持久化消息流 · 消费者组 · ACK 机制 · 类 Kafka 语义
底层实现

底层用 Rax（基数树）+ listpack 实现。Rax 是前缀压缩树，按消息 ID 索引，每个叶节点指向一个 listpack，批量存储连续消息（macro node），大幅节省内存。

消息 ID 格式为 毫秒时间戳-序列号，天然有序，可按时间范围查询。

消费者组维护 PEL（Pending Entry List），记录已投递但未 ACK 的消息，保证 at-least-once 语义。XACK 后从 PEL 删除。

常用命令
XADD key [MAXLEN ~N] * field value
追加消息，* 自动生成 ID。MAXLEN ~ N 近似裁剪流长度（性能更好）。
XREAD [COUNT n] [BLOCK ms] STREAMS key id
读取消息，从指定 ID 之后。BLOCK 0 永久阻塞等待新消息。
XGROUP CREATE key group id
创建消费者组。id=$ 从最新消息开始；id=0 从头消费。
XREADGROUP GROUP g consumer STREAMS key >
> 表示取未投递消息，消息进入 PEL 等待 ACK。
XACK key group id [id ...]
确认处理完毕，从 PEL 删除。未 ACK 消息可通过 XPENDING 查看。
可靠消息队列（比 List 更完善） 多消费者组并行消费 事件溯源 实时日志收集
底层基础结构

SDS Simple Dynamic String

所有字符串底层。头部含 len（已用）/ alloc（已分配），O(1) 取长度，无需遍历 \0。

预分配：修改时新长度 <1 MB 则翻倍分配，>1 MB 则多分配 1 MB，减少 realloc 次数。惰性释放：缩短字符串不立即释放，记入 free 留给下次。

根据长度自动选 sdshdr5 / 8 / 16 / 32 / 64，极短字符串几乎零浪费。二进制安全，可存 \0。

skiplist 跳跃表

多层有序链表。每个节点随机决定层数（晋升概率 25%，上限 32 层）。查找从最高层开始逐层下降，平均 O(log N)。

为什么不用红黑树：① 范围查询直接沿底层链表遍历，更简单；② 实现代码量小，逻辑清晰；③ 实测性能相近；④ 锁粒度更易控制。

Sorted Set 中与 hashtable 双索引，member 字符串指针共享，不重复存储。

listpack 紧凑列表 Redis 7.0+

替代 ziplist，修复连锁更新问题。每个 entry 结构：encoding + data + element-tot-len（自身总长），不存前驱长度。修改某 entry 只需更新自身，不影响后续节点。

顺序遍历高效（缓存友好），随机访问 O(N)，因此仅在小规模下使用。List / Hash / ZSet / Set 的紧凑编码均已切换为 listpack。

hashtable + 渐进式 rehash dict

内部维护 ht[0] 和 ht[1] 两张哈希表。MurmurHash2 计算键哈希，开链法解决冲突。

渐进式 rehash：扩容时 ht[1] 按新尺寸创建，rehashidx 记录当前迁移桶位置。每次读写顺带迁移一个桶，直到 ht[0] 清空。迁移期间读写同时查两表，彻底避免 STW 抖动。

负载因子 >1 扩容（BGSAVE 期间阈值升至 5），<0.1 缩容。

intset 整数集合

有序整数数组，支持 int16 / int32 / int64 三种编码，按实际最大值自动升级（只升不降）。

插入 / 查找用二分查找 O(log N)，内存连续，CPU 缓存命中率极高。元素全为整数且数量少时性能甚至优于 hashtable。一旦插入非整数立即整体转换为 hashtable。

quicklist 快速列表

双向链表，每个节点是一个 listpack 页（默认每页最多 128 个元素）。头尾操作只动链表头/尾节点的 listpack，O(1)；中间插入需定位节点，O(N)。

可配置 list-compress-depth 对中间节点做 LZF 压缩，进一步节省内存，两端节点不压缩保证热点访问速度。

TIP

紧凑编码连续内存存储，CPU 缓存命中率高，小数据下可能快于散列结构。用 OBJECT ENCODING key 查看当前编码。编码只升不降——删元素后不会自动退回紧凑编码。生产中调整阈值前先 benchmark，不要盲目设大。
