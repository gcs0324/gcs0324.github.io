为什么需要记忆
核心矛盾

LLM 的上下文窗口是 固定大小的工作区，而真实协作中的信息是无限增长的。即使窗口扩大到 1M token，"大海捞针"测试也只能测单事实检索——多事实场景下平均召回率仅约 60%，且模型在窗口中间位置的注意力显著下降（Lost in the Middle 效应）。

记忆系统的本质任务：从无限信息流中，把对当前决策最有价值的那一小撮信息捞出来，塞进有限的上下文窗口。

没有记忆系统
单次问答模式
每次对话从零开始。Agent 不记得你的偏好、项目背景、上次讨论到哪了。适合一次性任务，无法支撑长期协作。
有记忆系统
长期协作模式
Agent 记住你的技术栈偏好、项目架构、历史决策。新对话开始时自动加载相关上下文，越用越懂你。
关键数字

RAG（检索增强）vs 直接塞 1M token 长上下文的成本差距约 1,250 倍。1M token 缓存需要约 100GB GPU 显存。生产环境中，RAG 的实际可靠上限是 32K-64K token，而非模型宣传的最大值。

CoALA · 认知架构理论框架
为什么先讲理论

CoALA（Cognitive Architectures for Language Agents，Sumers & Yao, TMLR 2024）是第一篇系统化梳理 LLM Agent 认知架构的学术论文。它提出的四种记忆分类——Working / Episodic / Semantic / Procedural——已成为业内讨论 Agent 记忆的通用语言。理解 CoALA 后再看各框架实现，会发现它们都在这个框架的不同位置做了取舍。

CoALA 的理论来源是 SOAR 认知架构（非 ACT-R），核心创新是用自然语言统一所有内部表示，用 LLM 替代手写产生式规则。

记忆类型存什么生命周期类比
Working Memory
工作记忆		当前决策循环中的活跃信息：感知输入、LLM 推理中间结果、从长期记忆检索到的内容、当前目标状态每次决策循环后消失，除非显式写入长期记忆RAM
Episodic Memory
情景记忆		过去的交互轨迹：输入-输出对、事件流、对话历史、Agent 自身行为记录长期保留，可被后续检索与反思个人日记
Semantic Memory
语义记忆		关于世界与自身的结构化知识：实体、关系、从经验中抽象出的规则长期保留，可由外部知识库初始化维基百科
Procedural Memory
程序性记忆		决定 Agent 如何行动的机制：隐式部分（LLM 权重）+ 显式部分（Agent 代码、推理策略、检索逻辑）由设计者初始化，风险最高OS 内核
决策循环CoALA Decision Cycle
1
Observation（感知）
环境输入（用户消息、工具返回、API 响应）→ 写入 Working Memory
2
Planning（规划）
从长期记忆检索相关知识 → LLM 推理生成候选动作 → 对候选动作评估打分 → 选择最优动作
3
Execution（执行）
执行选定动作——可能是外部动作（调工具、发消息）或内部学习动作（写记忆、更新知识）
4
Feedback（反馈）
动作结果返回 Working Memory，循环回到 Planning
认知心理学渊源

CoALA 对应 SOAR 的四个组件：Working Memory → 工作记忆，Procedural Memory → 产生式规则，Semantic Memory → 语义长期记忆，Episodic Memory → 情景长期记忆。决策循环对应 SOAR 的 propose → evaluate → select → execute。SOAR 的 Chunking（经验压缩）对应 CoALA 的 Learning actions。

Generative Agents · 三维评分与反思机制
为什么重要

Park et al. (UIST 2023) 的 Generative Agents 是第一个完整实现 LLM Agent 长期记忆系统的工程。它提出的三维评分公式（recency + importance + relevance）已经成为后续几乎所有 Agent 记忆检索的事实标准。配套的 Reflection 机制首次实现了"记忆的记忆"——Agent 不仅能记住发生了什么，还能对自己的经历进行反思和抽象。

评分公式Memory Stream 三维检索评分
R
Recency（近因性）
公式：0.995^h，h = 自上次访问以来的游戏小时数。指数衰减，值域 [0, 1]。越近访问的记忆得分越高。
I
Importance（重要性）
LLM 打分 1-10。Prompt：「1=琐事（刷牙），10=极其重要（分手/录取）」。写入记忆时评分一次，后续不更新。
R
Relevance（相关性）
当前查询 embedding 与记忆 embedding 的余弦相似度。值域 [-1, 1]，需 min-max 归一化到 [0, 1]。
// 三维加权求和，默认权重均为 1.0 score = α · n(recency) + β · n(importance) + γ · n(relevance) // 关键配置 RECENCY_DECAY = 0.995 // 每小时指数衰减因子 REFLECTION_THRESHOLD = 150.0 // 触发反思的累积 importance 阈值
反思机制Reflection · 记忆的记忆
1
触发条件
最近记忆的 importance 总分超过 150
2
生成问题
取最近 100 条记忆作为种子，LLM 提出 3 个高层次问题
3
检索+综合
对每个问题检索相关记忆，LLM 综合生成 3-5 条 reflection statements（depth=2），30 天后过期
4
递归反思
反思产生的记忆可作为更高层反思的种子，形成记忆的树状结构
设计洞察

原始记忆（observation）和反思记忆（reflection）并存而非替代。检索时两者共同参与评分。这意味着 Agent 既能看到原始细节，也能利用高层抽象——类似人既记得"上周三下雨"（具体事件），也记得"最近天气不好"（抽象总结）。

怎么看这张表

每个框架对"记忆"的定义不同，分层数从 2 到 7 不等。关键是理解设计哲学的分歧：有人把记忆当作 Tool 让 LLM 主动调用，有人把记忆自动注入 prompt；有人用向量数据库做语义检索，有人用纯文件系统追求可审计性。没有银弹，只有取舍。

MemGPT / LettaOS 式分页记忆
1
核心洞察
把记忆从"存储问题"升级为"调度问题"。类比 OS 虚拟内存：主上下文 = RAM，外部存储 = 磁盘，LLM 通过函数调用自主决定何时换页。
2
三层架构
Core Memory（始终在上下文，2000 字符/块）→ Recall Memory（完整对话历史，SQL + 向量双写）→ Archival Memory（无限容量，向量检索）
3
FIFO + 递归摘要
主上下文对话历史用 FIFO 队列。被逐出的消息在队首维护递归摘要，完整消息可通过 Recall Storage 重新检索回主上下文。
Claude Code文件式记忆 · 可审计优先
1
设计哲学
可审计性优于查询能力。不使用向量数据库，所有记忆都是纯 Markdown 文件，用户可直接阅读、编辑、删除。
2
四类记忆
user（用户偏好）、feedback（行为纠正）、project（项目上下文）、reference（外部系统指针）。MEMORY.md 索引 + 按需 Read 主题文件。
3
注入方式
作为用户消息注入（非 system prompt），概率性遵守。加载有优先级顺序：组织级 → 用户级 → 项目级 → 本地，越靠后优先级越高。
ChatGPTDreaming V3 · 后台异步合成
1
三层子系统
Recent Messages（当日连贯性）→ Chat History（摘要 + 向量检索）→ User Insights（跨多轮高阶分析，贡献 ~80% 个性化提升）
2
后台异步处理
不在对话中实时写入。对话结束后批量扫描：提取长期有效信息、丢弃临时噪声、处理冲突与更新、标注置信度。
3
算力优化
服务免费用户所需算力降至旧版 1/5。美国 Plus/Pro 用户记忆容量 ×2。注意：Dreaming 不对 API 开放。
CrewAI统一 Memory + 层级 Scope
1
统一 API
用单个 Memory 类取代传统四层分类，通过 Scope（/company/engineering, /project/alpha）实现层级隔离。
2
双模式召回
Shallow（纯向量，~200ms）和 Deep（查询分析 → scope 选择 → 并行向量搜索 → 递归探索）。自适应深度，低分触发深度探索。
3
非阻塞写入
写入异步非阻塞，但 recall() 前自动 drain_writes()（读屏障），保证读取时能看到之前所有写入。
检索评分算法
评分公式是记忆系统的核心

记忆系统的好坏，最终体现在"给定当前查询，能不能把最相关的记忆捞出来"。各框架的评分公式看起来不同，但底层都在回答同一个问题：如何在语义相关性、时间近因性、内容重要性之间做权衡。

框架 / 论文评分公式权重时间衰减
Generative Agentsα·recency + β·importance + γ·relevanceα=β=γ=1.00.995^h（指数）
HelloAgents 情景(向量相似度×0.8 + 近因×0.2) × (0.8 + 重要性×0.4)内嵌e^(-0.1·age_hours/24)
HelloAgents 语义(向量相似度×0.7 + 图相似度×0.3) × (0.8 + 重要性×0.4)内嵌—
CrewAIsemantic×0.5 + recency×0.3 + importance×0.2可配置0.5^(age/half_life)，默认 30 天
FadeMemα·rel(c_i,Q_t) + β·f_i/(1+f_i) + γ·recency(τ_i,t)可调拉伸指数 e^(-λ·t^β)，β=0.8(LML)/1.2(SML)
FadeMem生物学启发的遗忘机制（arXiv 2601.18642）
1
双层记忆
LML（Long-term Memory Layer，慢遗忘，半衰期 ~11.25 天）和 SML（Short-term Memory Layer，快遗忘，半衰期 ~5.02 天）。
2
重要性调节衰减率
λ_i = λ_base · e^(-μ · I_i(t))。高重要性记忆衰减速度比 baseline 慢 3-5 倍。23% 的低重要性记忆因高频访问被提升到 LML。
3
实验数据
关键事实保留率 82.1%（vs LangChain 71.2%, Mem0 78.4%），存储用量仅 55%。
时间衰减函数
六种常见形式
  • 指数衰减 e^(-λt) — Generative Agents
  • 幂律衰减 1/(1+αt) — MemoryBank
  • 半衰期 0.5^(t/half_life) — CrewAI
  • 拉伸指数 e^(-λ·t^β) — FadeMem
  • 高斯衰减 e^(-t²/2σ²) — 实验性
  • 饱和函数 f/(1+f) — FadeMem 访问频率
重要度计算
四种计算方式
  • 规则-based：关键词/长度/模式匹配，快但泛化差
  • LLM-based：让 LLM 打 1-10 分，灵活但成本高、不稳定
  • 混合：规则初筛 + LLM 精评，Mem0 / FadeMem 采用
  • 频率-based：访问次数 + 时间衰减，自动无额外成本
存储与检索技术
向量数据库选型

不是所有记忆系统都需要向量数据库（Claude Code 就是纯文件），但如果你要做语义检索，选对向量数据库影响很大。核心考量：数据规模、是否需要混合检索（BM25 + 向量）、延迟预算、运维意愿。

原型验证 → Chroma；已有 PostgreSQL + 数据量 < 500 万 → PGVector；不想管服务器 → Pinecone；百万~千万级 + 自托管 → Qdrant（性能与易用最佳平衡）；亿级以上 + 有专职运维 → Milvus；多模态搜索 → Weaviate。

生产级检索混合检索三阶段管道
1
双路并行检索
BM25（精确匹配，top-50~500）并行 稠密向量（语义匹配，top-50~500）。两者互补：BM25 擅长错误代码、SKU 编号；向量擅长模糊语义查询。
2
RRF 融合排序
RRFscore(d) = Σ 1/(k + rank_i(d))，k=60。完全忽略原始分数差异，无需归一化。k=30~40 重视 top-1 精度，k=80~100 重视跨列表共识。
3
Cross-Encoder 重排序
top-50~200 → top-3~5。Benchmark 数据：混合+重排序 vs 纯稠密，Recall@5 提升 +39%（0.587 → 0.816）。代价：额外延迟 +100~300ms。

关键设计决策
决策 1Tool 调用 vs 自动注入
自动注入：核心人格、稳定信息始终在 prompt 中（Letta Core Memory、ChatGPT Saved Memories）。简单但占用窗口。

Tool 调用：长尾记忆按需检索（Letta Archival、HelloAgents MemoryTool）。精准但依赖 LLM 判断何时调用。

最佳实践：混合。核心在场 + 长尾按需。
决策 2同步 vs 异步写入
现代系统（ChatGPT Dreaming V3、AutoGPT Dream Pass、Gemini Memory Bank）趋向异步后台处理——对话结束后批量提取、整合、去重。

好处：不增加实时延迟，可做批量成本优化（Anthropic Batch API 50% 折扣）。
决策 3向量 vs 文件 vs 图
向量：语义检索，适合大规模模糊匹配
文件：可审计，适合开发者工具（Claude Code）
图：关系推理，适合多跳查询和事实校验

Mem0 的方案是三路融合。
记忆生命周期写入 → 检索 → 遗忘 → 整合
W
写入策略
全量记录（早期 AutoGPT，已证明失败）→ 重要性过滤（LLM 打分）→ ADD-only（Mem0，不覆盖旧事实，新旧并存保留时间上下文）
F
遗忘策略
重要性淘汰（Mem0 四操作 ADD/UPDATE/DELETE/NOOP）、时间淘汰（CrewAI 半衰期 30 天）、容量淘汰（FIFO/LRU）、搜索降权（不删除，仅降低权重）
C
整合 Consolidation
Working → Episodic → Semantic 的升级路径。Generative Agents 的 Reflection、CrewAI 的相似度合并（阈值 0.85）、AutoGPT Dream Pass 的三阶段巩固（NREM→REM→净化）
