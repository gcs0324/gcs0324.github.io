2. checked vs unchecked

受检异常（Checked）非受检异常（Unchecked）
继承Exception（非 RuntimeException）RuntimeException 或 Error
编译要求必须 try-catch 或 throws 声明无需声明
语义可恢复的外部错误（IO、网络）编程错误、不可恢复
典型例子IOException, SQLExceptionNPE, ArrayIndexOutOfBounds
业界争议Spring 推荐转为非受检抛出更简洁
💡 Spring 将大量受检异常（如 SQLException）包装为 DataAccessException（非受检），调用者无需强制处理，更简洁。

3. 异常最佳实践

try-with-resources（JDK 7）

// AutoCloseable 资源自动关闭
try (InputStream in = new FileInputStream("f.txt");
     BufferedReader br = new BufferedReader(new InputStreamReader(in))) {
    String line;
    while ((line = br.readLine()) != null) { ... }
} catch (IOException e) {
    log.error("read failed", e);
}
// 编译器自动生成 finally 中的 close()，抑制异常通过 addSuppressed 保留

常见反模式

  • ❌ catch(Exception e){} 吞掉异常，排查极难
  • ❌ e.printStackTrace() 生产用日志框架
  • ❌ 用异常控制业务流程（性能差）
  • ❌ 抛出过于宽泛的异常 throws Exception
  • ✅ 携带上下文信息：new ServiceException("userId=" + id, e)
  • ✅ 层间转换：DAO 层的 SQLException → Service 层业务异常
// 自定义业务异常（推荐）
public class BizException extends RuntimeException {
    private final int code;
    public BizException(int code, String msg) {
        super(msg);
        this.code = code;
    }
    public BizException(int code, String msg, Throwable cause) {
        super(msg, cause);
        this.code = code;
    }
}

4. BIO 模型

BIO（Blocking I/O）：每个连接一个线程，阻塞等待 IO 完成。简单但不适合高并发。

// BIO 服务器：每连接创建一个线程
ServerSocket server = new ServerSocket(8080);
while (true) {
    Socket socket = server.accept();  // 阻塞等待连接
    new Thread(() -> handle(socket)).start(); // 一连接一线程
}
// 问题：C10K —— 1万连接需要1万线程，内存爆炸

5. NIO 核心

NIO（Non-blocking I/O，JDK 1.4）：多路复用，单线程处理多个连接。三大核心：Buffer、Channel、Selector。

组件说明关键方法
Buffer数据容器（ByteBuffer等），有 position/limit/capacityput/get/flip/clear/compact
Channel双向数据通道（vs BIO 的单向 Stream）read/write/register
SelectorIO 多路复用，监听多个 Channel 事件select/selectedKeys/register
// NIO Selector 服务器模型（简化）
Selector selector = Selector.open();
ServerSocketChannel ssc = ServerSocketChannel.open();
ssc.configureBlocking(false);   // 非阻塞模式
ssc.register(selector, SelectionKey.OP_ACCEPT);

while (true) {
    selector.select();  // 阻塞直到有事件
    Set<SelectionKey> keys = selector.selectedKeys();
    for (SelectionKey key : keys) {
        if (key.isAcceptable()) {
            SocketChannel sc = ssc.accept();
            sc.configureBlocking(false);
            sc.register(selector, SelectionKey.OP_READ);
        } else if (key.isReadable()) {
            SocketChannel sc = (SocketChannel) key.channel();
            ByteBuffer buf = ByteBuffer.allocate(1024);
            sc.read(buf);
            // 处理数据...
        }
    }
    keys.clear();
}
💡 Netty 基于 NIO 实现，封装了 Selector 的复杂性，提供 EventLoop、Pipeline、Handler 抽象，是高性能网络框架的事实标准。

6. AIO 模型

AIO（Asynchronous I/O，JDK 7）：真正的异步，IO 操作完成后回调通知，适合长连接/大文件传输。Linux 下基于 epoll 模拟，Windows 下基于 IOCP 原生支持。

AsynchronousSocketChannel asc = AsynchronousSocketChannel.open();
asc.read(buffer, null, new CompletionHandler<Integer,Void>() {
    @Override public void completed(Integer result, Void attachment) {
        // IO 完成回调
    }
    @Override public void failed(Throwable e, Void attachment) {
        // 异常处理
    }
});

7. IO 模型对比

模型特点线程数适用场景
BIO同步阻塞，简单直观连接数量连接数少，调试简单

AIO异步非阻塞，回调通知更少高并发长连接、大文件
