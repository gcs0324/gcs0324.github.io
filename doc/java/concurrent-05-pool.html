01ThreadPoolExecutor — 7 个核心参数
构造函数参数
new ThreadPoolExecutor(
    int corePoolSize,        // ① 核心线程数（常驻线程）
    int maximumPoolSize,     // ② 最大线程数
    long keepAliveTime,      // ③ 非核心线程空闲存活时间
    TimeUnit unit,           // ④ 时间单位
    BlockingQueue workQueue, // ⑤ 任务等待队列
    ThreadFactory factory,   // ⑥ 线程创建工厂（命名、异常处理）
    RejectedExecutionHandler // ⑦ 拒绝策略
);
① corePoolSize
核心线程数，创建后不会销毁（即使空闲），除非 allowCoreThreadTimeOut=true
② maximumPoolSize
线程池最大线程数。队列满后，若当前线程数 < max，创建非核心线程
③④ keepAlive
非核心线程空闲超过此时间则销毁，直到线程数等于 corePoolSize
⑤ workQueue
任务等待队列：有界队列（ArrayBQ）/ 无界队列（LinkedBQ）/ 直接传递（SynchronousQ）
⑥ threadFactory
创建线程的工厂，可自定义线程名称、优先级、未捕获异常处理器（强烈建议自定义命名）
⑦ handler
队列满且线程数达 max 时的拒绝策略（4种内置 + 自定义）
02任务执行流程
提交任务的判断优先级
线程数 < core创建新核心线程执行
→
线程数 ≥ core放入工作队列等待
→
队列已满线程数 < max则创建非核心线程
→
线程数 = max且队列满，执行拒绝策略
关键细节：线程数先达到 core 就入队，不是先扩到 max 再入队。这是很多人的误区！只有队列满了才会创建非核心线程。
// execute() vs submit()
executor.execute(runnable);           // 无返回值，异常直接抛出
Future<T> f = executor.submit(callable); // 有返回值，异常封装在 Future 中
034 种拒绝策略
内置拒绝策略对比
策略行为适用场景
AbortPolicy（默认）抛出 RejectedExecutionException需要明确感知任务被拒绝
CallerRunsPolicy由调用 execute() 的线程直接执行不丢任务，通过降低提交速度形成反压
DiscardOldestPolicy丢弃队列最老的任务，尝试重新提交优先保留最新任务
DiscardPolicy静默丢弃，不抛异常允许丢失任务（如非关键日志）
生产建议：绝大多数场景用 CallerRunsPolicy（不丢任务 + 自动限流）；关键业务用自定义策略（记录日志、写入 DB 或 MQ 补偿）。
04线程数配置公式
CPU 密集 vs IO 密集
任务类型推荐线程数说明
CPU 密集型N + 1N = CPU 核数。+1 防止偶发中断导致 CPU 空闲，多了反而增加上下文切换
IO 密集型2N 或更多线程等待 IO 时 CPU 空闲，可利用更多线程充分利用 CPU
混合型N / (1 - 阻塞系数)阻塞系数 = IO 时间 / (IO + CPU 时间)，例如 80% 时间等IO，系数=0.8，则 N/0.2 = 5N
公式仅是起点：实际需要通过压测观察 CPU 利用率、响应时间、队列积压情况动态调整。美团有"动态线程池"实践可参考。
自定义线程池最佳实践
// 推荐写法：有界队列 + 明确命名 + CallerRunsPolicy
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    10,                          // core：根据压测设定
    20,                          // max
    60L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(1000),  // 有界队列！
    new ThreadFactoryBuilder()
        .setNameFormat("order-pool-%d")  // 命名便于排查
        .setUncaughtExceptionHandler((t, e) -> log.error("线程异常", e))
        .build(),
    new ThreadPoolExecutor.CallerRunsPolicy() // 反压
);

// 优雅关闭
executor.shutdown();           // 不接受新任务，等已有任务完成
executor.awaitTermination(30, TimeUnit.SECONDS);
// 若超时还没完成
executor.shutdownNow();        // 发送 interrupt() 信号给所有线程
054 种内置线程池（Executors 工厂）
内置线程池对比
名称core/max队列风险
FixedThreadPool(n)n/nLinkedBlockingQueue（无界）队列无界，OOM
CachedThreadPool0/Integer.MAXSynchronousQueue线程数无限，OOM
SingleThreadExecutor1/1LinkedBlockingQueue（无界）队列无界，OOM
ScheduledThreadPool(n)n/Integer.MAXDelayedWorkQueue线程数无限，OOM
阿里 Java 规范：禁止使用 Executors 工厂方法创建线程池。原因：FixedThreadPool/SingleThreadExecutor 使用无界队列，可能堆积大量请求导致 OOM；CachedThreadPool 可创建 Integer.MAX_VALUE 个线程，同样 OOM 风险。应使用 ThreadPoolExecutor 构造函数明确指定所有参数。

07线程池生命周期状态
5 种状态转换
状态说明转换触发
RUNNING正常运行，接受新任务，处理队列任务初始状态
SHUTDOWN不接受新任务，继续处理队列中的任务shutdown()
STOP不接受新任务，不处理队列任务，中断执行中的任务shutdownNow()
TIDYING所有任务终止，workerCount=0，将执行 terminated()自动过渡
TERMINATEDterminated() 执行完毕terminated() 返回

状态值存储在 AtomicInteger 的高 3 位（与 workerCount 共用一个变量，RUNNING=-1<<29 为负数）。

08ForkJoinPool
工作窃取算法

ForkJoinPool 每个线程有自己的双端任务队列（Deque），线程从队列头取任务，若自己的队列空了，则从其他线程队列尾部窃取任务，减少竞争：

// RecursiveTask（有返回值）示例：并行求和
class SumTask extends RecursiveTask<Long> {
    private final long[] arr;
    private final int from, to;
    static final int THRESHOLD = 1000;

    @Override
    protected Long compute() {
        if (to - from <= THRESHOLD) {
            // 任务足够小，直接计算
            long sum = 0;
            for (int i = from; i < to; i++) sum += arr[i];
            return sum;
        }
        // 任务太大，分裂
        int mid = (from + to) / 2;
        SumTask left  = new SumTask(arr, from, mid);
        SumTask right = new SumTask(arr, mid, to);
        left.fork();               // 异步提交左半部分
        return right.compute()     // 当前线程计算右半部分
             + left.join();        // 等待左半部分结果
    }
}

ForkJoinPool pool = new ForkJoinPool(Runtime.getRuntime().availableProcessors());
long result = pool.invoke(new SumTask(arr, 0, arr.length));
并行流与 ForkJoinPool：list.parallelStream() 底层使用 ForkJoinPool.commonPool()（全局共享，默认 CPU 核数-1）。若需要控制并行度或隔离，应显式提交到自定义 ForkJoinPool。
