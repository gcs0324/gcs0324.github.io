Spring Kafka 是对原生 Kafka Client 的封装，核心价值：自动装配、声明式消费（@KafkaListener）、与 Spring 事务体系集成，以及完善的错误处理与重试机制。

依赖 + application.yml 最小配置
<!-- pom.xml —— Spring Boot 3.x 自动管理版本 -->
<dependency>
    <groupId>org.springframework.kafka</groupId>
    <artifactId>spring-kafka</artifactId>
</dependency>
# application.yml — 最小配置
spring:
  kafka:
    bootstrap-servers: localhost:9092

    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer
      acks: all
      retries: 3
      properties:
        enable.idempotence: true       # 开启幂等（自动设置 acks=all、retries=MAX）

    consumer:
      group-id: my-group
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
      auto-offset-reset: earliest
      enable-auto-commit: false         # 关闭自动提交
      properties:
        spring.json.trusted.packages: "com.example.dto"  # JsonDeserializer 信任包

    listener:
      ack-mode: manual_immediate        # 手动即时提交
      concurrency: 3                    # 并发消费线程数（建议 = Partition 数）
Spring Boot 自动装配：KafkaAutoConfiguration 根据 spring.kafka.* 自动创建 KafkaTemplate、ConsumerFactory、ProducerFactory Bean。如需自定义（多集群、特殊序列化），手动定义这些 Bean 即可覆盖。
自定义 Factory — 多集群 / 自定义序列化
@Configuration
public class KafkaConfig {

    // 主集群 Producer（高可靠配置）
    @Bean
    public ProducerFactory<String, Object> producerFactory() {
        Map<String, Object> cfg = new HashMap<>();
        cfg.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG, "broker1:9092,broker2:9092");
        cfg.put(ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG, StringSerializer.class);
        cfg.put(ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG, JsonSerializer.class);
        cfg.put(ProducerConfig.ACKS_CONFIG, "all");
        cfg.put(ProducerConfig.ENABLE_IDEMPOTENCE_CONFIG, true);
        cfg.put(JsonSerializer.ADD_TYPE_INFO_HEADERS, false); // 不在 Header 中写类型信息
        return new DefaultKafkaProducerFactory<>(cfg);
    }

    @Bean
    public KafkaTemplate<String, Object> kafkaTemplate() {
        return new KafkaTemplate<>(producerFactory());
    }

    // 从集群 Consumer（不同 bootstrap-servers）
    @Bean("secondaryConsumerFactory")
    public ConsumerFactory<String, Object> secondaryConsumerFactory() {
        Map<String, Object> cfg = new HashMap<>();
        cfg.put(ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG, "broker3:9092");
        cfg.put(ConsumerConfig.GROUP_ID_CONFIG, "secondary-group");
        cfg.put(ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG, StringDeserializer.class);
        cfg.put(ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG, JsonDeserializer.class);
        cfg.put(JsonDeserializer.TRUSTED_PACKAGES, "com.example.dto");
        return new DefaultKafkaConsumerFactory<>(cfg);
    }
}
02KafkaTemplate 发消息
三种发送模式
@Service
@RequiredArgsConstructor
public class OrderMessageService {

    private final KafkaTemplate<String, OrderEvent> kafkaTemplate;

    // ① 发后即忘（fire-and-forget）— 不关心结果，吞吐最高
    public void sendFireAndForget(OrderEvent event) {
        kafkaTemplate.send("order-topic", event.getOrderId(), event);
    }

    // ② 异步回调（Spring 3.x+ 返回 CompletableFuture）— 推荐
    public void sendAsync(OrderEvent event) {
        kafkaTemplate.send("order-topic", event.getOrderId(), event)
            .whenComplete((result, ex) -> {
                if (ex != null) {
                    log.error("消息发送失败 orderId={}", event.getOrderId(), ex);
                    alertService.sendAlert("Kafka 发送失败: " + event.getOrderId());
                } else {
                    log.debug("发送成功 partition={} offset={}",
                        result.getRecordMetadata().partition(),
                        result.getRecordMetadata().offset());
                }
            });
    }

    // ③ 同步发送 — 强可靠场景，会阻塞当前线程
    public void sendSync(OrderEvent event) throws Exception {
        SendResult<String, OrderEvent> result =
            kafkaTemplate.send("order-topic", event.getOrderId(), event)
                .get(10, TimeUnit.SECONDS);  // 最多阻塞 10s
        log.info("同步发送成功 partition={} offset={}",
            result.getRecordMetadata().partition(),
            result.getRecordMetadata().offset());
    }
}
⚠ 同步发送注意：.get() 会阻塞当前线程，在 Broker 繁忙或网络波动时会显著降低吞吐量，仅在强一致性要求的场景（如支付确认）使用。
ProducerListener — 全局发送钩子
@Bean
public KafkaTemplate<String, Object> kafkaTemplate(ProducerFactory<String, Object> pf) {
    KafkaTemplate<String, Object> template = new KafkaTemplate<>(pf);
    template.setProducerListener(new ProducerListener<>() {
        @Override
        public void onSuccess(ProducerRecord<String, Object> record, RecordMetadata metadata) {
            // 统计发送成功计数（可接入 Micrometer Metrics）
            meterRegistry.counter("kafka.send.success",
                "topic", record.topic()).increment();
        }

        @Override
        public void onError(ProducerRecord<String, Object> record,
                            RecordMetadata metadata, Exception ex) {
            log.error("Kafka 全局发送失败 topic={} key={}", record.topic(), record.key(), ex);
            alertService.sendAlert("Kafka 发送失败！topic=" + record.topic());
        }
    });
    return template;
}
携带 Headers：通过 new ProducerRecord<>(topic, partition, key, value, headers) 传递自定义 Header，常用于传递链路追踪 TraceId（X-Trace-Id）实现跨服务追踪。
03@KafkaListener 消费
基础用法 — 常用参数一览
@Component
public class OrderConsumer {

    // 最简单：监听 Topic，使用配置文件中的 group-id
    @KafkaListener(topics = "order-topic")
    public void consume(OrderEvent event) {
        process(event);
    }

    // 完整参数版：手动 ack + 获取元数据
    @KafkaListener(
        topics       = "order-topic",
        groupId      = "order-service",
        concurrency  = "3",   // 等价于 3 个 Consumer 实例，Rebalance 后各自分到不同 Partition
        containerFactory = "kafkaListenerContainerFactory"
    )
    public void consumeWithMeta(
            OrderEvent event,
            @Header(KafkaHeaders.RECEIVED_PARTITION) int partition,
            @Header(KafkaHeaders.OFFSET)             long offset,
            Acknowledgment ack) {
        try {
            process(event);
            ack.acknowledge();   // 处理成功，手动提交 Offset
        } catch (Exception e) {
            log.error("消费失败 partition={} offset={}", partition, offset, e);
            throw e;  // 抛出异常，交给 ErrorHandler 处理（重试 or DLT）
        }
    }

    // 监听多 Topic
    @KafkaListener(topics = {"order-topic", "payment-topic"}, groupId = "audit-group")
    public void multiTopic(ConsumerRecord<String, String> record) {
        log.info("topic={} partition={} key={}",
            record.topic(), record.partition(), record.key());
    }
}
⚠ concurrency ≤ Partition 数：超出 Partition 数的线程无法分到任何 Partition，空转浪费资源。建议 concurrency 设置为 Partition 数，让每个线程独占一个 Partition。
批量消费 — 高吞吐入库场景
# application.yml — 开启批量监听
spring:
  kafka:
    listener:
      type: batch
// 批量消费，一次处理一批 records
@KafkaListener(topics = "order-topic")
public void consumeBatch(
        List<ConsumerRecord<String, OrderEvent>> records,
        Acknowledgment ack) {

    List<OrderEvent> events = records.stream()
        .map(ConsumerRecord::value)
        .collect(Collectors.toList());

    orderRepository.saveAll(events);  // 批量入库，1 次 IO 代替 N 次

    ack.acknowledge();  // 提交整批 Offset
    log.info("批量消费 {} 条", events.size());
}

// 更简洁写法（直接接收 List<T>）
@KafkaListener(topics = "order-topic")
public void consumeSimple(List<OrderEvent> events) {
    orderRepository.saveAll(events);
}
批量消费需配合 max.poll.records（默认 500）控制批次大小。若单批处理时间过长超过 max.poll.interval.ms，会触发 Rebalance。高峰期可临时调小 max.poll.records。
消息过滤 — RecordFilterStrategy
@Bean
public ConcurrentKafkaListenerContainerFactory<String, OrderEvent>
        kafkaListenerContainerFactory(ConsumerFactory<String, OrderEvent> cf) {

    var factory = new ConcurrentKafkaListenerContainerFactory<String, OrderEvent>();
    factory.setConsumerFactory(cf);

    // 过滤策略：只处理 status=CREATED 的订单
    // 返回 true = 过滤掉，不传给 @KafkaListener 方法
    factory.setRecordFilterStrategy(record ->
        !"CREATED".equals(record.value().getStatus()));

    factory.setAckDiscarded(true);  // 过滤的消息自动提交 Offset
    return factory;
}
04错误处理与死信队列
DefaultErrorHandler + ExponentialBackOff

Spring Kafka 2.8+ 统一用 DefaultErrorHandler 处理所有消费异常（替代旧版 SeekToCurrentErrorHandler）：

@Bean
public DefaultErrorHandler errorHandler(KafkaTemplate<String, Object> kafkaTemplate) {

    // 指数退避：1s → 2s → 4s → ... 最大 30s，总超时 2min
    ExponentialBackOff backOff = new ExponentialBackOff();
    backOff.setInitialInterval(1_000L);
    backOff.setMultiplier(2.0);
    backOff.setMaxInterval(30_000L);
    backOff.setMaxElapsedTime(120_000L);

    // 失败消息转发到 {topic}.DLT（Partition 保持一致）
    DeadLetterPublishingRecoverer recoverer =
        new DeadLetterPublishingRecoverer(kafkaTemplate);

    DefaultErrorHandler handler = new DefaultErrorHandler(recoverer, backOff);

    // 不重试的异常（重试也没意义，直接进 DLT）
    handler.addNotRetryableExceptions(
        DeserializationException.class,
        ClassCastException.class,
        IllegalArgumentException.class
    );

    return handler;
}

@Bean
public ConcurrentKafkaListenerContainerFactory<?, ?> kafkaListenerContainerFactory(
        ConsumerFactory<String, Object> cf,
        DefaultErrorHandler errorHandler) {
    var factory = new ConcurrentKafkaListenerContainerFactory<String, Object>();
    factory.setConsumerFactory(cf);
    factory.setCommonErrorHandler(errorHandler);
    return factory;
}

// DLT 消费者：监听死信，告警 + 持久化供人工查看
@KafkaListener(topics = "order-topic.DLT", groupId = "order-dlt-group")
public void consumeDlt(
        ConsumerRecord<String, OrderEvent> record,
        @Header(KafkaHeaders.EXCEPTION_MESSAGE)  String errorMsg,
        @Header(KafkaHeaders.ORIGINAL_TOPIC)     String originalTopic,
        @Header(KafkaHeaders.ORIGINAL_PARTITION) int originalPartition,
        @Header(KafkaHeaders.ORIGINAL_OFFSET)    long originalOffset) {

    log.error("💀 DLT 消息 topic={} partition={} offset={} error={}",
        originalTopic, originalPartition, originalOffset, errorMsg);

    // 写入数据库，供运营人员查看和手动重投
    dltRepository.save(DltRecord.of(
        originalTopic, originalOffset, record.value(), errorMsg));

    alertService.send("❗ 死信消息告警 topic=" + originalTopic);
}
DLT Header 包含完整上下文：ORIGINAL_TOPIC、ORIGINAL_PARTITION、ORIGINAL_OFFSET、EXCEPTION_MESSAGE、EXCEPTION_STACKTRACE，可精确定位问题消息。
05事务与 Spring 集成
KafkaTransactionManager — 与 @Transactional 集成
// 配置 KafkaTransactionManager
@Bean
public KafkaTransactionManager<String, Object> kafkaTxManager(
        DefaultKafkaProducerFactory<String, Object> pf) {
    pf.setTransactionIdPrefix("tx-order-");  // 设置 transactional.id 前缀
    return new KafkaTransactionManager<>(pf);
}
// 发消息 + 写 DB 原子性（注意：需使用 ChainedTxManager 才能真正绑定 DB 事务）
@Service
@RequiredArgsConstructor
public class OrderService {

    private final OrderRepository orderRepository;
    private final KafkaTemplate<String, OrderEvent> kafkaTemplate;

    @Transactional("kafkaTxManager")
    public void createOrder(Order order) {
        // 1. 保存到 DB（若 DB 回滚，Kafka 事务也会 abort）
        orderRepository.save(order);

        // 2. 发送 Kafka 消息（在同一 Kafka 事务内）
        kafkaTemplate.send("order-topic", order.getId(),
            new OrderCreatedEvent(order.getId(), order.getAmount()));

        // 抛出异常时：
        // Kafka：Producer.abortTransaction() —— 消息不可见
        // DB：Spring 事务回滚
    }
}
⚠ Kafka 事务 ≠ 分布式事务：KafkaTransactionManager 只管理 Kafka Producer 事务，与数据库事务不绑定。要实现 Kafka + DB 原子提交，需要 ChainedKafkaDatabaseTransactionManager 或本地消息表方案（推荐，实现更简单可靠）。
Consume-Transform-Produce（CTP）— Exactly-Once 管道

消费一个 Topic → 处理 → 发送到另一个 Topic，整个过程在同一 Kafka 事务内：

// Consumer 端开启事务支持
@Bean
public ConcurrentKafkaListenerContainerFactory<?, ?> transactionalFactory(
        ConsumerFactory<String, Object> cf,
        KafkaTransactionManager<String, Object> txManager) {
    var factory = new ConcurrentKafkaListenerContainerFactory<String, Object>();
    factory.setConsumerFactory(cf);
    factory.getContainerProperties().setTransactionManager(txManager);
    return factory;
}
// CTP：消费 raw-orders → 加工 → 发布到 enriched-orders，Exactly-Once
@KafkaListener(topics = "raw-orders", containerFactory = "transactionalFactory")
@Transactional("kafkaTxManager")
public void processAndForward(OrderEvent raw) {
    OrderEvent enriched = enrich(raw);  // 业务加工

    kafkaTemplate.send("enriched-orders", enriched.getOrderId(), enriched);
    // 事务提交时：
    // ① enriched-orders 消息对消费者可见
    // ② raw-orders 的 Offset 被提交
    // 任何步骤失败 → 两者同时回滚，raw-orders 消息重新被消费
}
# Consumer 需要 read_committed 隔离级别，过滤未提交事务的消息
spring:
  kafka:
    consumer:
      properties:
        isolation.level: read_committed
CTP 是 Kafka Streams 的核心语义。纯业务项目中，若复杂度不高，本地消息表 + 定时重发是更易维护的最终一致性方案，不需要引入 Kafka 事务。
