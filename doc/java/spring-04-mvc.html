01HTTP 请求处理完整流程
DispatcherServlet 处理流程（8步）
①
请求进入 DispatcherServlet
所有请求统一由前端控制器 DispatcherServlet 接收（配置 / 或 /*），是整个 MVC 的核心枢纽
②
HandlerMapping — 路由匹配
根据请求 URL、HTTP 方法等查找对应的 Handler（Controller 方法），同时组装拦截器链（HandlerExecutionChain）
③
HandlerAdapter — 适配执行
不同类型的 Handler 需要不同的 Adapter 执行；@RequestMapping 方法由 RequestMappingHandlerAdapter 处理
④
拦截器 preHandle()
在 Handler 执行前调用所有拦截器的 preHandle()，返回 false 则终止请求链，直接响应
⑤
Handler（Controller）方法执行
参数绑定（@RequestBody 由 HttpMessageConverter 反序列化），执行业务逻辑，返回结果
⑥
拦截器 postHandle()
Handler 执行后、视图渲染前调用，可修改 ModelAndView；异常时不调用
⑦
视图渲染 / 响应写出
REST 场景：@ResponseBody 用 HttpMessageConverter 序列化，直接写出响应体。传统 MVC：ViewResolver 解析视图名，渲染模板
⑧
拦截器 afterCompletion()
请求完成后调用（无论是否异常），用于资源清理。异常时也会被调用

04拦截器 vs 过滤器
Filter vs HandlerInterceptor 对比
维度Filter（过滤器）HandlerInterceptor（拦截器）
规范Servlet 规范（javax/jakarta.servlet）Spring MVC 特有
作用位置最外层，DispatcherServlet 之外DispatcherServlet 内部
拦截范围所有请求（含静态资源、其他 Servlet）仅 DispatcherServlet 管控的请求
访问 Spring Bean需手动获取 ApplicationContext直接 @Autowired 注入
方法doFilter()（单方法，链式调用）preHandle / postHandle / afterCompletion
能访问 Handler 信息❌ 不能✅ 可以（Object handler 参数）
注册方式@WebFilter 或 FilterRegistrationBeanWebMvcConfigurer#addInterceptors
// Filter 注册
@Bean
public FilterRegistrationBean<MyFilter> authFilter() {
    FilterRegistrationBean<MyFilter> bean = new FilterRegistrationBean<>();
    bean.setFilter(new MyFilter());
    bean.addUrlPatterns("/api/*");
    bean.setOrder(1); // 数值越小越先执行
    return bean;
}

// Interceptor 注册
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new AuthInterceptor())
            .addPathPatterns("/api/**")
            .excludePathPatterns("/api/login");
    }
}
05参数绑定原理
HandlerMethodArgumentResolver

Spring MVC 通过 HandlerMethodArgumentResolver 接口的实现类将 HTTP 请求中的数据绑定到 Controller 方法参数：

  • ▸RequestParamMethodArgumentResolver → 处理 @RequestParam
  • ▸PathVariableMethodArgumentResolver → 处理 @PathVariable
  • ▸RequestResponseBodyMethodProcessor → 处理 @RequestBody / @ResponseBody（通过 HttpMessageConverter）
  • ▸ServletModelAttributeMethodProcessor → 处理 @ModelAttribute
06HttpMessageConverter
内容协商与转换流程

@RequestBody 和 @ResponseBody 都依赖 HttpMessageConverter 完成序列化/反序列化：

请求反序列化：读 Content-Type → 找支持该媒体类型的 Converter → 调用 read() → Java 对象

响应序列化：读 Accept 头 → 内容协商 → 找支持的 Converter → 调用 write() → 写入响应体

Converter支持格式
MappingJackson2HttpMessageConverterapplication/json（默认，Jackson）
StringHttpMessageConvertertext/plain, text/*
ByteArrayHttpMessageConverterapplication/octet-stream
Jaxb2RootElementHttpMessageConverterapplication/xml, text/xml
FastJsonHttpMessageConverterapplication/json（FastJSON，需手动注册）
07全局异常处理
@ControllerAdvice + @ExceptionHandler（推荐）
@RestControllerAdvice // = @ControllerAdvice + @ResponseBody
public class GlobalExceptionHandler {

    // 处理业务异常
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusiness(BusinessException e) {
        return Result.fail(e.getCode(), e.getMessage());
    }

    // 处理参数校验异常（@Valid 失败）
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidation(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors()
            .stream().map(FieldError::getDefaultMessage)
            .collect(Collectors.joining(", "));
        return Result.fail(400, msg);
    }

    // 处理所有未捕获异常（兜底）
    @ExceptionHandler(Exception.class)
    public Result<Void> handleAll(Exception e) {
        log.error("系统异常", e);
        return Result.fail(500, "服务器内部错误");
    }
}
08参数校验
Bean Validation 常用注解
注解说明
@NotNull不能为 null
@NotBlank不能为 null 且去空格后长度 > 0（String 专用）
@NotEmpty不能为 null 且不能为空（Collection/String/Array）
@Size(min,max)大小范围限制
@Min / @Max数值最小值 / 最大值
@Pattern(regexp)正则表达式匹配
@Email邮箱格式
@Valid级联校验（嵌套对象）
@Valid vs @Validated：@Valid 是 JSR-303 标准注解；@Validated 是 Spring 扩展，支持分组校验（groups 参数），可针对不同操作使用不同校验规则（如 Create 和 Update）。
