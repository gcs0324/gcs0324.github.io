01自动装配原理
从 @SpringBootApplication 到装配执行

@SpringBootApplication 是三个注解的组合：

@SpringBootConfiguration    // 等同于 @Configuration，声明配置类
@EnableAutoConfiguration    // ← 自动装配核心入口
@ComponentScan              // 扫描主类所在包及子包
①
@EnableAutoConfiguration
通过 @Import(AutoConfigurationImportSelector.class) 导入自动配置选择器
②
SPI 加载候选配置类
Boot 2.x：扫描所有 jar 包 META-INF/spring.factories，读取 key 为 EnableAutoConfiguration 的配置类列表（可能 100+ 个）
Boot 3.x：改为读取 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
③
@Conditional 条件过滤
对每个候选配置类进行条件检查，不满足条件的跳过（绝大多数情况下大量配置类被过滤掉）
④
注册满足条件的配置类
通过条件的 AutoConfiguration 类被注册为 BeanDefinition，后续正常走 Spring IoC 容器的 Bean 创建流程
02@Conditional 条件注解
常用 Conditional 注解
注解条件说明
@ConditionalOnClassclasspath 中存在指定类时生效（最常用）
@ConditionalOnMissingClassclasspath 中不存在指定类时生效
@ConditionalOnBean容器中存在指定 Bean 时生效
@ConditionalOnMissingBean容器中不存在指定 Bean 时生效（允许用户自定义覆盖）
@ConditionalOnProperty配置文件中指定属性满足条件时生效
@ConditionalOnWebApplication是 Web 应用时生效
@ConditionalOnExpressionSpEL 表达式为 true 时生效
@ConditionalOnJavaJava 版本满足条件时生效
用户覆盖原理：AutoConfiguration 通常在 @Bean 上加 @ConditionalOnMissingBean，如果用户已注册同类型的 Bean，则自动配置的 Bean 跳过，实现"约定优于配置"。
03SpringApplication 启动流程
SpringApplication.run() 核心步骤
①
创建 SpringApplication 对象
推断应用类型（Servlet Web / Reactive Web / None），通过 SPI 加载 ApplicationContextInitializer 和 ApplicationListener 列表
②
发布 ApplicationStartingEvent
通知监听器应用即将启动
③
prepareEnvironment()
创建 ConfigurableEnvironment，加载配置源（application.yml / 环境变量 / 命令行参数），发布 ApplicationEnvironmentPreparedEvent
④
createApplicationContext()
根据应用类型创建 ApplicationContext（Servlet Web → AnnotationConfigServletWebServerApplicationContext）
⑤
prepareContext()
执行 ApplicationContextInitializer，注册主启动类为 BeanDefinition
⑥ ★
refreshContext() — Spring IoC 核心
执行 AbstractApplicationContext#refresh() 的 12 步，包含自动装配配置类加载、所有 Bean 的实例化。Web 容器在 onRefresh() 阶段创建并启动内嵌 Tomcat
⑦
afterRefresh() + Runner
执行所有 CommandLineRunner 和 ApplicationRunner（按 @Order 排序），发布 ApplicationReadyEvent
04配置体系与优先级
配置源优先级（从高到低）
优先级配置源
最高命令行参数（--server.port=8081）
↓Java 系统属性（-Dserver.port=8081）
↓操作系统环境变量（SERVER_PORT=8081）
↓application-{profile}.yml（Profile 配置文件）
↓application.yml（默认配置文件）
最低@PropertySource 注解导入的配置
高优先级的配置会覆盖低优先级的相同 key，这是实现多环境配置的基础。
@ConfigurationProperties 类型安全绑定
# application.yml
mail:
  host: smtp.gmail.com
  port: 587
  username: user@gmail.com

// Java 类型安全绑定
@ConfigurationProperties(prefix = "mail")
@Component // 或在 @EnableConfigurationProperties 中注册
public class MailProperties {
    private String host;
    private int port;
    private String username;
    // getter/setter...
}

相比 @Value("${mail.host}")，@ConfigurationProperties 支持复杂对象绑定、集合绑定，且可在 IDE 中自动补全（需引入 spring-boot-configuration-processor）。

05Profile 多环境配置
Profile 使用方式
# 激活 Profile
spring.profiles.active=prod  # application.yml 中配置
# 或命令行：--spring.profiles.active=prod
# 或环境变量：SPRING_PROFILES_ACTIVE=prod

# application-dev.yml（开发环境）
spring.datasource.url=jdbc:mysql://localhost:3306/dev_db

# application-prod.yml（生产环境）
spring.datasource.url=jdbc:mysql://prod-server:3306/prod_db
// 代码中的 Profile 条件
@Configuration
@Profile("dev")  // 仅在 dev Profile 下生效
public class DevDataConfig {
    @Bean
    public DataSource dataSource() {
        return new EmbeddedDatabaseBuilder().setType(H2).build();
    }
}
06自定义 Starter
Starter 标准结构

推荐分两个模块：

  • ▸xxx-spring-boot-autoconfigure：包含自动配置类、Properties 类、核心功能代码
  • ▸xxx-spring-boot-starter：仅含 pom.xml，依赖 autoconfigure 模块，供用户引入
①
编写 AutoConfiguration 类
@AutoConfiguration（Boot 3.x）或 @Configuration（Boot 2.x），用 @ConditionalOn* 控制装配条件
②
编写 ConfigurationProperties
@ConfigurationProperties(prefix="xxx") 定义配置项，提供 IDE 补全支持
③
注册 AutoConfiguration（Boot 2.x）
在 META-INF/spring.factories 中：org.springframework.boot.autoconfigure.EnableAutoConfiguration=com.xxx.XxxAutoConfiguration
③
注册 AutoConfiguration（Boot 3.x）
在 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports 中写入配置类全路径
④
添加 configuration-processor 依赖
生成 META-INF/spring-configuration-metadata.json，IDE 自动补全配置项提示
07Actuator 监控
常用端点
端点说明
/actuator/health健康状态检查（数据库连接、磁盘空间等）
/actuator/metrics应用指标（JVM 内存、线程数、HTTP 请求数等）
/actuator/env环境配置信息（配置属性）
/actuator/beans所有 Spring Bean 列表
/actuator/mappings所有 @RequestMapping 路由映射
/actuator/loggers日志级别查看与动态修改
/actuator/threaddump线程堆栈信息
/actuator/heapdump下载堆内存 dump 文件
/actuator/info应用信息（git 版本、构建信息等）
# 开放端点配置（生产环境谨慎开放）
management:
  endpoints:
    web:
      exposure:
        include: health,metrics,info  # 或 * 开放所有
  endpoint:
    health:
      show-details: always  # 显示详细健康信息
08Spring Boot 3.x 重要变化
Boot 3.x vs 2.x 主要差异
变化点Boot 2.xBoot 3.x
最低 Java 版本Java 8+Java 17+
最低 Spring 版本Spring 5.xSpring 6.x
Servlet APIjavax.servlet.*jakarta.servlet.*（全面迁移 Jakarta EE 9+）
AutoConfiguration 注册spring.factoriesAutoConfiguration.imports 文件
原生镜像实验性支持一等公民，AOT 编译，GraalVM Native Image
声明式 HTTP 客户端需 Feign原生 @HttpExchange（替代 Feign）
可观测性MicrometerMicrometer Tracing + OpenTelemetry 集成
迁移注意：2.x → 3.x 最大痛点是 javax → jakarta 包名变更，所有代码中的 import 都需修改。可使用 spring-boot-migrator 工具辅助迁移。
