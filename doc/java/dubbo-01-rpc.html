1. 什么是 RPC

RPC（Remote Procedure Call，远程过程调用）：调用远程服务就像调用本地方法一样，屏蔽网络通信细节。

核心组成：服务注册中心 + 序列化 + 网络传输 + 动态代理。

2. RPC vs HTTP

维度RPC（如 Dubbo）HTTP（REST / gRPC）
协议自定义二进制（Dubbo Protocol）HTTP/1.1 或 HTTP/2
数据格式Hessian / Protobuf（二进制）JSON（文本）/ Protobuf
性能更高（二进制小包）相对低（JSON 大）
耦合度高（共享接口 jar）低（契约/文档驱动）
跨语言弱（语言绑定）强
适用内部微服务（同技术栈）对外 API / 多语言
代表Dubbo, gRPC, ThriftSpring MVC, Feign
💡 gRPC 是基于 HTTP/2 + Protobuf 的 RPC，兼顾跨语言与高性能，适合云原生场景。

3. RPC 调用流程

  1. 服务注册：Provider 启动时向注册中心注册服务元数据（IP、端口、接口、版本）
  2. 服务发现：Consumer 启动时从注册中心订阅服务，获取 Provider 地址列表
  3. 代理生成：Consumer 通过动态代理生成本地 Stub，调用 Stub 如同调用本地方法
  4. 参数序列化：将方法名、参数类型、参数值序列化为字节流
  5. 网络传输：通过 TCP 长连接（Netty）将请求发送到 Provider
  6. 反序列化：Provider 端反序列化请求，通过反射调用目标方法
  7. 结果返回：将返回值序列化后，通过同一 TCP 连接返回
  8. Consumer 接收：反序列化结果，代理层返回给调用方

4. 序列化

序列化框架格式性能跨语言适用场景
Java 原生二进制慢❌不推荐（Serializable 安全问题）
JSON（Jackson/Gson）文本中✅对外接口，可读性好
Hessian二进制较快部分Dubbo 默认
Protobuf二进制最快✅gRPC，跨语言高性能
Kryo二进制最快❌JVM 内部，如 Spark
FST二进制快❌纯 Java 高性能

序列化关键注意点

  • 字段增减需向后兼容（Protobuf 通过 tag 号实现，Hessian 通过字段名）
  • 避免序列化敏感字段（密码等），用 transient 或 @JsonIgnore
  • Java 原生序列化存在安全漏洞（反序列化攻击），生产禁用
  • 循环引用需特殊处理（Jackson @JsonIdentityInfo）

5. 网络传输

为什么用 TCP 长连接？

  • 避免每次请求建立 TCP 三次握手的开销
  • Dubbo 默认每个 Provider 地址保持一条 TCP 长连接，通过多路复用
  • 连接池管理复用，保持心跳

Netty 线程模型

// Dubbo 基于 Netty 的 Reactor 模型
Boss EventLoop Group  ← 接收连接
    ↓
Worker EventLoop Group ← IO 读写（反序列化、路由）
    ↓
Business Thread Pool  ← 业务逻辑执行（避免阻塞 IO 线程）

粘包/半包问题

TCP 是流协议，无消息边界。RPC 通过定长头部（Header）+ 消息体长度解决：

Dubbo 协议帧：
┌─────────────────────────────────────────────────────┐
│ Magic(2B) │ Flag(1B) │ Status(1B) │ RequestID(8B) │ DataLength(4B) │ Body │
└─────────────────────────────────────────────────────┘
- 固定 16 字节头，Body 长度由 DataLength 指定
- Netty LengthFieldBasedFrameDecoder 按帧解码

6. 动态代理

Consumer 调用的"接口"实际是动态代理生成的 Stub，代理拦截方法调用，组装 Request，通过网络发送。

// Dubbo 使用 Javassist（默认）或 JDK 动态代理
// Consumer 侧：通过代理将方法调用转为网络请求
@Reference
UserService userService; // 实际是代理对象

userService.getUser(1L); // 代理拦截 → 序列化 → TCP → Provider

// Proxy 核心逻辑
public Object invoke(Object proxy, Method method, Object[] args) {
    RpcInvocation inv = new RpcInvocation(method, args);
    return invoker.invoke(inv).recreate(); // 发出请求，等待响应
}

7. 协议设计要点

要素说明
魔数（Magic）快速识别协议，如 Dubbo 用 0xdabb
版本号协议向后兼容，支持协议升级
序列化类型告知对端使用何种序列化
请求 ID异步请求-响应匹配（Future Map）
消息类型区分请求/响应/心跳
数据长度解决 TCP 粘包半包
状态码SUCCESS/ERROR/SERVER_TIMEOUT 等
