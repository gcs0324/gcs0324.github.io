1. 四大角色

角色职责说明
Provider（服务提供者）暴露服务启动时向注册中心注册，监听端口等待调用
Consumer（服务消费者）调用服务从注册中心订阅，获取地址列表后发起调用
Registry（注册中心）服务注册发现ZooKeeper / Nacos / Redis 等
Monitor（监控中心）统计调用收集调用次数、耗时、异常，可选组件
// 调用关系
Provider ──注册──▶ Registry ◀──订阅── Consumer
Provider ◀─────────────────────────── Consumer（直接调用，注册中心可不在线）
Provider ──统计──▶ Monitor ◀──统计── Consumer

层次组件作用

💡 Dubbo 分层设计体现了"关注点分离"，每层只依赖下层，通过 SPI 可替换任意层的实现。

3. SPI 扩展机制

Java SPI vs Dubbo SPI

Java SPIDubbo SPI
配置文件位置META-INF/services/META-INF/dubbo/
加载方式一次加载所有实现按需加载（key=class）
IoC 支持❌✅（自动注入 setter）
AOP 支持❌✅（Wrapper 机制）
自适应扩展❌✅（@Adaptive 根据 URL 参数动态选择）
// Dubbo SPI 配置文件：META-INF/dubbo/com.alibaba.dubbo.rpc.Protocol
dubbo=com.alibaba.dubbo.rpc.protocol.dubbo.DubboProtocol
http=com.alibaba.dubbo.rpc.protocol.http.HttpProtocol
injvm=com.alibaba.dubbo.rpc.protocol.injvm.InjvmProtocol

// 使用
@SPI("dubbo")  // 默认扩展名
public interface Protocol {
    @Adaptive  // 自适应：根据 URL 的 protocol 参数选择实现
    Exporter<?> export(Invoker<?> invoker);
}

// 加载扩展
Protocol protocol = ExtensionLoader
    .getExtensionLoader(Protocol.class)
    .getExtension("dubbo");

4. 服务导出（Provider 启动）

  1. 解析配置：读取 ServiceConfig，收集接口、实现类、协议、注册中心等配置
  2. 创建 Invoker：通过 ProxyFactory 将服务实现包装为 Invoker
  3. 导出 URL：构建 dubbo://host:port/interface?params 格式 URL
  4. 本地导出：InjvmProtocol 导出（同 JVM 内调用）
  5. 远程导出：DubboProtocol.export() → Netty 启动监听端口
  6. 注册到注册中心：RegistryProtocol → ZooKeeper/Nacos 写入节点
// URL 样例
dubbo://192.168.1.100:20880/com.example.UserService
    ?application=user-provider
    &methods=getUser,listUsers
    &version=1.0.0
    &timeout=3000
    &serialization=hessian2

5. 服务引入（Consumer 启动）

  1. 解析 @Reference：Spring BeanPostProcessor 处理 ReferenceConfig
  2. 从注册中心订阅：RegistryDirectory 监听 ZooKeeper 节点，获取 Provider 列表
  3. 创建 Directory：保存 URL → Invoker 映射，随注册中心变化动态更新
  4. 创建 Cluster Invoker：包装容错策略（FailoverClusterInvoker 等）
  5. 创建代理：ProxyFactory.getProxy() 生成动态代理，注入到 Spring Bean

6. Filter 链

Dubbo Filter 是 AOP 机制，通过 SPI + Wrapper 实现链式拦截，类似 Servlet Filter。

内置 Filter作用侧（P=Provider, C=Consumer）
TimeoutFilter超时检测P
TokenFilterToken 鉴权P
ExceptionFilter异常统一处理P
MonitorFilter调用统计P + C
ActiveLimitFilter并发数控制C
CacheFilter结果缓存C
ConsumerContextFilter传递 RPC 上下文C
// 自定义 Filter
@Activate(group = {CommonConstants.CONSUMER})
public class TraceFilter implements Filter {
    @Override
    public Result invoke(Invoker<?> invoker, Invocation inv) throws RpcException {
        String traceId = UUID.randomUUID().toString();
        RpcContext.getContext().setAttachment("traceId", traceId);
        return invoker.invoke(inv);  // 责任链传递
    }
}

7. 配置体系

配置级别（优先级高→低）方式
方法级配置（Consumer）@Reference(methods={@Method(name="...",timeout=100)})
接口级配置（Consumer）@Reference(timeout=1000)
接口级配置（Provider）@Service(timeout=2000)
全局配置（Consumer）dubbo.consumer.timeout=3000
全局配置（Provider）dubbo.provider.timeout=5000
💡 Consumer 配置优先于 Provider 配置，方法级配置优先于接口级配置，接口级配置优先于全局配置。
