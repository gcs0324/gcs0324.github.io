CH 01 JVM 内存模型与对象 jvm-01-memory.html 打开 →
01 · 运行时数据区
  • 程序计数器 — 线程私有，唯一无 OOM 区域
  • JVM 虚拟机栈 — 栈帧：局部变量表 / 操作数栈 / 动态链接 / 返回地址
  • 本地方法栈 — Native 方法执行
  • 堆（Heap） — Eden / S0 / S1 / Old Gen 分代布局
  • 方法区 → 元空间 — 类信息 / 运行时常量池 / 静态变量
  • 直接内存 — NIO ByteBuffer，不受 -Xmx 限制
02 · 对象创建过程
  • ① 类加载检查
  • ② 内存分配：指针碰撞 vs 空闲列表；TLAB 线程私有缓冲
  • ③ 零值初始化
  • ④ 设置对象头（Mark Word + Klass Pointer）
  • ⑤ 执行 <init>
03 · 对象内存布局
  • 对象头 — Mark Word（锁标志 / GC 年龄 / hashCode）
  • Klass Pointer — 指向方法区类元数据（开启压缩后 4 字节）
  • 实例数据 — 字段按类型对齐排列
  • 对齐填充 — 保证对象起始地址为 8 字节倍数
04 · 对象访问方式
  • 句柄池 — GC 移对象只改句柄，引用稳定
  • 直接指针（HotSpot 默认）— 少一次间接寻址，速度快
05 · OOM 类型与排查
  • Java heap space — 堆溢出，最常见
  • Metaspace — 动态代理 / CGLib 生成类过多
  • StackOverflowError — 递归无出口 / 栈帧过大
  • Direct buffer memory — 堆外内存耗尽
  • GC overhead limit exceeded — GC 时间占比 >98%
  • 排查工具：jmap / jhat / MAT / jstack / Arthas
CH 02 GC 算法与垃圾收集器 jvm-02-gc.html 打开 →
01 · 可达性分析
  • GC Roots — 栈变量 / 静态变量 / JNI 引用 / 同步锁对象
  • 引用类型：强引用 > 软引用 > 弱引用 > 虚引用
  • finalize() 二次标记机制（了解即可）
02 · 基础 GC 算法
  • 标记-清除 — 碎片问题，适合老年代
  • 标记-复制 — 新生代主流，空间利用率 50%
  • 标记-整理 — 无碎片，但整理开销大
  • 分代收集 — 新生代用复制，老年代用清除/整理
03 · 经典收集器
  • Serial / Serial Old — 单线程 STW，Client 模式
  • ParNew — Serial 多线程版，配合 CMS
  • Parallel Scavenge — 吞吐量优先，自适应调节
  • CMS — 初始标记(STW) → 并发标记 → 重新标记(STW) → 并发清除
  • CMS 痛点：浮动垃圾 / 并发模式失败 / 碎片问题
04 · G1 收集器（重点）
  • Region 设计 — E / S / O / H 动态分配，不再固定分代区域
  • SATB 写屏障 — 快照保证并发标记正确性
  • Remembered Set + Card Table — 跨 Region 引用追踪
  • GC 模式：Young GC / Mixed GC / Full GC / Concurrent Cycle
  • -XX:MaxGCPauseMillis 停顿预测模型
05 · ZGC / Shenandoah
  • ZGC — 着色指针 / 读屏障 / 并发整理，停顿 <1ms
  • 停顿时间不随堆大小增长（适合超大堆）
  • Shenandoah — Brooks 转发指针，Region-based
06 · GC 调优实战
  • 核心参数：-Xms / -Xmx / -Xmn / -XX:NewRatio
  • GC 日志解读：-Xlog:gc* 格式说明
  • 常见问题：频繁 Full GC / 长 STW / 内存抖动
  • 调优思路：确认问题类型 → 选收集器 → 调参数 → 验证
CH 03 类加载机制与双亲委派 jvm-03-classload.html 打开 →
01 · 类的生命周期
  • 加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载
  • 主动使用（触发初始化）vs 被动使用（不触发）
02 · 五个加载阶段
  • 加载 — .class 字节流 → 方法区 + 堆中 Class 对象
  • 验证 — 文件格式 / 元数据 / 字节码 / 符号引用
  • 准备 — static 变量分配内存，赋零值（≠ 初始值）
  • 解析 — 符号引用 → 直接引用（类 / 字段 / 方法）
  • 初始化 — 执行 <clinit>，static 块 + 静态赋值
03 · 类加载器体系
  • Bootstrap ClassLoader — C++ 实现，加载 rt.jar
  • Extension / Platform CL — 加载 ext/ 目录
  • Application ClassLoader — 加载 classpath
  • 自定义 ClassLoader — 继承 ClassLoader，重写 findClass
04 · 双亲委派模型
  • 加载请求逐级向上委派，只有父级加载不了才自己处理
  • 作用：防止核心类被替换（保证 java.lang.Object 唯一）
  • 破坏场景：SPI / JNDI（线程上下文类加载器）
  • 破坏场景：Tomcat — 同名类隔离不同 WebApp
  • 破坏场景：OSGi — 模块化网状委派
05 · 热部署原理
  • 类的卸载条件：ClassLoader 实例被回收 + Class 对象无引用
  • 热部署原理：创建新 ClassLoader 加载新版本类，替换旧引用
  • Arthas 热更新：redefine / retransform 命令原理
  • OSGI / Spring DevTools 热重载实现方式
