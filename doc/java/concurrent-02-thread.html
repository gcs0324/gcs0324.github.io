Callable + Future 示例
// Callable：有返回值，可抛异常
Callable<Integer> task = () -> {
    Thread.sleep(1000);
    return 42;
};

// FutureTask 包装 Callable
FutureTask<Integer> future = new FutureTask<>(task);
new Thread(future).start();

// get() 阻塞直到结果可用
Integer result = future.get();       // 阻塞等待
Integer result2 = future.get(2, TimeUnit.SECONDS); // 超时等待

// CompletableFuture（推荐，支持异步编排）
CompletableFuture<Integer> cf =
    CompletableFuture.supplyAsync(() -> 42, executor)
        .thenApply(r -> r * 2)
        .exceptionally(e -> 0);

状态说明触发条件

04线程中断机制
interrupt() 工作原理

Java 线程中断是协作式的，interrupt() 只设置中断标志位，不强制停止线程。线程需主动检查并响应：

// 设置中断标志
thread.interrupt();

// 检查中断标志（不清除）
if (Thread.currentThread().isInterrupted()) { ... }

// 检查中断标志并清除（静态方法）
if (Thread.interrupted()) { ... }

// 可中断阻塞方法（sleep/wait/join）收到中断会抛 InterruptedException
// 并清除中断标志！捕获后应恢复标志位
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt(); // 恢复中断标志
    return; // 退出线程
}
stop() 已废弃：Thread.stop() 强制停止会导致监视器解锁、数据不一致等问题，已废弃。应使用 interrupt() 协作中断或 volatile 标志位优雅停止。
05ThreadLocal
实现原理

每个线程内部有一个 ThreadLocalMap（类似 HashMap），key 是 ThreadLocal 对象（弱引用），value 是存储的值：

Thread
  └── threadLocals: ThreadLocalMap
        └── Entry[] table
              └── Entry(WeakReference<ThreadLocal>, Object value)

// 读取：Thread.currentThread().threadLocals.get(this)
threadLocal.get()
// 写入：Thread.currentThread().threadLocals.set(this, value)
threadLocal.set(value)
内存泄漏问题

Entry 的 key（ThreadLocal）是弱引用，当 ThreadLocal 对象不再被强引用时 key 会被 GC 回收变为 null，但 value 是强引用仍然存在，导致内存泄漏：

  • 原因线程池中线程长期存活，线程的 ThreadLocalMap 也长期存在，null key 的 Entry 无法被回收
  • 解决每次使用完 ThreadLocal 后显式调用 threadLocal.remove()，最佳实践是在 try-finally 中确保 remove()
try {
    userContext.set(currentUser);
    // ... 业务逻辑
} finally {
    userContext.remove(); // 必须！防止内存泄漏和数据错乱
}
线程池场景必须 remove()：线程被复用时，上一次请求残留的 ThreadLocal 值会被下一个请求读到，导致数据污染。
InheritableThreadLocal — 父子线程传值

普通 ThreadLocal 子线程无法获取父线程的值；InheritableThreadLocal 在子线程创建时拷贝父线程的 inheritableThreadLocals，实现父子线程数据传递。

线程池场景：由于线程是复用的，InheritableThreadLocal 只在线程创建时复制，无法解决线程池问题。推荐使用阿里开源的 TransmittableThreadLocal（TTL）。

06线程协作（wait/notify）
wait / notify 使用规范

wait() 和 notify() 必须在 synchronized 块内调用（否则抛 IllegalMonitorStateException）：

// 生产者-消费者模式
class BoundedBuffer {
    private final Queue<Integer> queue = new LinkedList<>();
    private final int capacity = 10;

    public synchronized void put(int item) throws InterruptedException {
        while (queue.size() == capacity) { // ← 必须用 while，防虚假唤醒
            wait();
        }
        queue.add(item);
        notifyAll(); // 唤醒所有等待者
    }

    public synchronized int take() throws InterruptedException {
        while (queue.isEmpty()) { // ← 必须用 while
            wait();
        }
        int item = queue.poll();
        notifyAll();
        return item;
    }
}
为什么用 while 而不是 if？虚假唤醒（Spurious Wakeup）：线程可能在没有被 notify 的情况下从 wait() 返回（操作系统层面行为）。用 while 可以在唤醒后重新检查条件，若条件不满足继续等待。Java 官方文档明确要求必须用 while。
07守护线程
守护线程 vs 用户线程
维度用户线程（User Thread）守护线程（Daemon Thread）
生命周期独立，JVM 等待所有用户线程结束才退出依附于用户线程，所有用户线程退出后自动终止
设置方式默认start() 前调用 setDaemon(true)
典型应用业务线程、主线程GC 线程、心跳检测、后台任务
finally 保证✅ 可靠❌ 不可靠（JVM 强制退出时 finally 不执行）
