01向量检索基础
什么是向量数据库

向量数据库是专门用于存储和检索高维向量的数据库。在 AI 应用中，文本、图片等非结构化数据通过 Embedding 模型转化为固定长度的数值向量（比如一段 300 词的文本变成一个 1536 维的浮点数组），向量数据库的核心能力就是快速找到与目标向量最相似的 Top-K 个向量。

  • 存储以向量为基本单元，同时支持存储原始文本、ID 等标量字段
  • 检索输入一条查询向量，返回语义最接近的 K 条结果，通常在毫秒级完成
  • 典型场景RAG（检索增强生成）、语义搜索、推荐系统、多模态检索
  • 核心指标召回率（能否找到正确的相似结果）和查询延迟（单次检索耗时）
向量 vs 关系型数据库
维度关系型数据库向量数据库
查询方式精确匹配：WHERE name = '张三'近似最近邻（ANN）：找语义最接近的 K 条
数据模型行/列结构，强 Schema向量 + 可选标量字段，Schema 灵活
索引目标等值查询、范围查询 O(log N)高维空间最近邻 O(log N) 或亚线性
事务支持ACID 事务多数不支持事务，侧重高吞吐写入
典型数据规模GB ~ TB百万 ~ 十亿条向量
典型引擎MySQL / PostgreSQLMilvus / Qdrant / Pinecone / Weaviate
能否用关系型数据库做向量检索？
PostgreSQL + pgvector 扩展支持向量存储和近似搜索，适合数据量 < 500 万且查询 QPS 低的场景。超过这个规模建议用专用向量数据库。
02相似度算法
余弦相似度 / 欧氏距离 / 内积

向量检索的本质是比较两个向量有多"接近"。不同算法衡量的维度不同，直接影响检索效果。

算法公式含义取值范围适用场景
余弦相似度两个向量夹角的余弦值，只看方向不看大小[-1, 1]，越大越相似文本语义搜索（最常用）；Embedding 模型输出已归一化时，等价于内积
欧氏距离两个向量在空间中的直线距离，值越小越相似[0, +∞)，越小越相似图像特征匹配、物理位置相近的检索
内积（Dot Product）对应维度相乘再求和，兼顾方向和大小无固定范围向量已归一化时等价余弦；推荐系统中需要考虑热度偏差时使用
面试要点
大多数 Embedding 模型（如 OpenAI text-embedding-3）输出的向量已经 L2 归一化，此时余弦相似度 = 内积，三者等价。选型时优先余弦，性能最优。

选择建议：文本语义搜索用余弦相似度；图像检索用欧氏距离；如果向量已归一化，三者效果相同，选计算最快的即可。

03索引算法
HNSW / IVF / PQ / Flat

全量遍历（Flat）每条查询都要比较所有向量，100 万条向量单次查询约 100ms。索引算法通过空间换时间，将查询加速到毫秒级。

算法原理内存占用召回率适用规模
Flat暴力搜索，逐个比较1x（仅原始数据）100%< 10 万条
HNSW构建多层跳表图结构，从顶层快速定位到目标区域再逐层细化~1.5x95-99%10 万 ~ 1 亿条（推荐）
IVF先用 K-Means 将向量聚成 N 个簇，检索时只搜索最近的若干簇~1.1x90-98%100 万 ~ 10 亿条
PQ将高维向量压缩为低维编码（如 1536 维 → 96 字节），大幅减少内存~0.1x85-95%1 亿条以上，内存受限
最佳实践
中小规模（< 1000 万条）优先选 HNSW：召回率高、查询快、实现简单。超大规模 + 内存受限选 IVF_PQ 组合（IVF 聚类 + PQ 压缩）。Flat 适合做召回率基准测试。

05性能调优
索引参数调优与资源规划

向量数据库的性能由召回率、查询延迟、内存占用三个指标决定，调优本质是在三者之间找平衡。

HNSW 关键参数
参数含义推荐值调大效果
M（最大连接数）每个节点最多连接的邻居数16 ~ 64召回率 ↑，内存 ↑，构建速度 ↓
ef_construction（构建时搜索宽度）插入新节点时搜索的候选集大小100 ~ 300索引质量 ↑，构建速度 ↓
ef_search（查询时搜索宽度）查询时搜索的候选集大小50 ~ 200召回率 ↑，延迟 ↑
资源规划参考
  • 内存估算1536 维 float32 向量：每条约 6KB（1536 × 4 字节）；HNSW 索引额外占用约 50-100%，即每条约 10-12KB
  • QPS 估算单节点（16 核 64GB）Milvus：HNSW 索引 100 万条向量，QPS 可达 1000-5000
  • 写入速度批量插入（batch insert）比逐条插入快 10-50 倍；建议每次写入 1000-5000 条
  • 磁盘索引Milvus 2.3+ 支持 DiskANN，将索引放磁盘，内存需求降低 80%，适合超大规模场景
常见坑
• ef_search 设置过低（< 30）导致召回率骤降到 70% 以下
• 插入数据后立即查询，索引尚未构建完成，需要等待 indexing 完成
• 未设置磁盘容量告警，索引写满磁盘后写入失败
06Java 集成
Spring AI + Milvus 实战

Spring AI 提供了对 Milvus 和 Qdrant 的开箱即用支持，通过 VectorStore 接口统一操作，切换数据库只需改配置。

  • 添加依赖spring-ai-milvus-store-spring-boot-starter（Milvus）或 spring-ai-qdrant-store-spring-boot-starter（Qdrant）
  • 配置连接application.yml 中设置 spring.ai.vectorstore.milvus.uri 和 collection-name；Milvus 默认端口 19530
  • 写入向量调用 vectorStore.add(List<Document>)，Spring AI 自动调用 Embedding 模型生成向量并存入数据库
  • 语义检索vectorStore.similaritySearch("查询文本", topK, similarityThreshold)，返回最相关的 Document 列表
  • 混合检索配合 KeywordAdvisor 或自定义 FilterExpression 实现关键词 + 向量的混合搜索
切换到 Qdrant
将 starter 换成 spring-ai-qdrant-store-spring-boot-starter，配置改为 spring.ai.vectorstore.qdrant.uri，业务代码无需修改（VectorStore 接口统一）。
