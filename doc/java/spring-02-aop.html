02动态代理
JDK 动态代理 vs CGLIB
维度JDK 动态代理CGLIB
代理方式实现目标接口，基于接口代理继承目标类，生成子类字节码
要求目标类必须实现接口目标类不能是 final，方法不能是 final
核心类java.lang.reflect.Proxy + InvocationHandlernet.sf.cglib.proxy.Enhancer + MethodInterceptor
性能创建快，invoke 通过反射较慢创建略慢（生成字节码），invoke 直接调用较快
Spring Boot 默认2.x 前默认（有接口时）Spring Boot 2.x 起默认
Spring Boot 2.x 为何改为默认 CGLIB？ JDK 代理要求注入时必须用接口类型接收代理对象，用实现类类型接收会注入失败；CGLIB 无此限制，更符合开发者直觉，减少因类型不匹配导致的启动报错。
CGLIB 代理示例
// 目标类（无需实现接口）
public class OrderService {
    public void createOrder() { System.out.println("创建订单"); }
}

// CGLIB 生成的子类（伪代码）
public class OrderService$$EnhancerBySpringCGLIB extends OrderService {
    @Override
    public void createOrder() {
        // 执行 Before 通知
        interceptor.before();
        // 调用父类方法
        super.createOrder();
        // 执行 After 通知
        interceptor.after();
    }
}
03切点表达式
常用切点表达式
表达式含义
execution(* com.service.*.*(..))service 包下所有类的所有方法
execution(* com.service..*.*(..))service 包及子包下所有类所有方法（.. 表示任意子包）
execution(public * *(..))所有 public 方法
@annotation(com.anno.Log)方法上有 @Log 注解
@within(org.springframework.web.bind.annotation.RestController)类上有 @RestController 注解的所有方法
bean(orderService)名为 orderService 的 Bean 的所有方法
args(java.lang.String,..)第一个参数为 String 类型的方法
// 复合表达式
@Pointcut("execution(* com.service..*.*(..)) && @annotation(com.anno.Log)")
public void logPointcut() {}

// 复用切点
@Before("logPointcut()")
public void before(JoinPoint jp) { ... }
04通知类型与执行顺序
5 种通知类型执行顺序（正常情况）
@Around (前半段)proceed() 之前的代码，最先执行
@Before目标方法执行前
[ 目标方法 ]实际业务逻辑执行
@AfterReturning目标方法正常返回后（异常时不执行）
@After相当于 finally，无论是否异常都执行
@Around (后半段)proceed() 之后的代码，最后执行

异常情况：@AfterReturning 不执行，改为执行 @AfterThrowing，之后执行 @After；@Around 中 proceed() 之后的代码不执行（异常会向上抛出）。

@Around 通知模板
@Around("execution(* com.service..*.*(..))")
public Object around(ProceedingJoinPoint pjp) throws Throwable {
    // 前置处理
    long start = System.currentTimeMillis();
    String methodName = pjp.getSignature().getName();
    Object[] args = pjp.getArgs();

    try {
        // 调用目标方法
        Object result = pjp.proceed();
        // 后置处理（正常返回）
        log.info("{} 执行成功，耗时 {}ms", methodName, System.currentTimeMillis() - start);
        return result;
    } catch (Throwable e) {
        // 异常处理
        log.error("{} 执行异常: {}", methodName, e.getMessage());
        throw e;
    }
}
05AOP 自调用失效
失效原因与解决方案

失效原因：Spring AOP 基于代理对象拦截。容器中存放的是代理对象，当类内部通过 this 调用方法时，this 指向原始对象，不经过代理，切面逻辑不执行。

// ❌ 自调用失效：this 是原始对象
@Service
public class OrderService {
    @Transactional
    public void createOrder() {
        this.sendEmail(); // @Async 不生效
    }
    @Async
    public void sendEmail() { ... }
}

// ✅ 方案1：注入自身代理（推荐）
@Service
public class OrderService {
    @Autowired
    private OrderService self; // 注入的是代理

    public void createOrder() {
        self.sendEmail(); // 经过代理，@Async 生效
    }
}

// ✅ 方案2：AopContext 获取代理
// 需开启 @EnableAspectJAutoProxy(exposeProxy=true)
((OrderService) AopContext.currentProxy()).sendEmail();
06多切面执行顺序
@Order 控制顺序

多个切面作用于同一方法时，通过 @Order(n) 控制，数值越小优先级越高，先入后出（类似栈）：

@Aspect @Order(1) // 优先级高
public class LogAspect {
    @Around("...") public Object log(...) { /* wrap */ }
}

@Aspect @Order(2) // 优先级低
public class AuthAspect {
    @Around("...") public Object auth(...) { /* wrap */ }
}

// 执行顺序：
// LogAspect.Around前 → AuthAspect.Around前 → [目标方法]
//   → AuthAspect.Around后 → LogAspect.Around后
07Spring AOP 实现原理
AnnotationAwareAspectJAutoProxyCreator 核心流程

@EnableAspectJAutoProxy 通过 @Import(AspectJAutoProxyRegistrar.class) 向容器注册 AnnotationAwareAspectJAutoProxyCreator（继承自 AbstractAutoProxyCreator，是一个 BeanPostProcessor）。

  • ①在 refresh() 第 6 步 registerBeanPostProcessors 阶段被注册
  • ②每个 Bean 初始化完成后，调用 postProcessAfterInitialization()
  • ③检查容器中所有 @Aspect 切面，找出能匹配该 Bean 方法的 Advisor
  • ④若有匹配，用 JDK 代理或 CGLIB 创建代理对象，将 Advisor 链织入
  • ⑤容器中注册代理对象，后续注入给其他 Bean 的都是代理
08Spring AOP vs AspectJ
核心区别
维度Spring AOPAspectJ
实现方式运行时动态代理（JDK/CGLIB）编译时 / 类加载时字节码织入
织入时机运行期编译期（ajc 编译器）或类加载期（Load-time Weaving）
切点范围仅 Spring 管理的 Bean 的方法执行任意 Java 代码（字段 / 构造器 / 静态方法等）
性能有代理调用开销编译时织入，几乎无运行时开销
配置复杂度简单，开箱即用需 AspectJ 编译器或 Java Agent
Spring 集成原生支持通过 spring-aspects 模块集成
注意：Spring AOP 使用 AspectJ 的注解语法（@Aspect、@Pointcut、@Before 等），但底层实现是动态代理，不是 AspectJ 的字节码织入。两者注解相同但机制不同。
