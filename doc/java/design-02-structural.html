1. 适配器模式 Adapter

意图：将不兼容的接口转换为客户期望的接口，让原本不能合作的类可以一起工作。

类适配器对象适配器（推荐）
实现方式继承被适配者组合被适配者
灵活性低（单继承限制）高（可适配子类）
// 场景：旧系统 OldLogger，新系统用 Logger 接口
interface Logger { void log(String msg, Level level); }
class OldLogger { void writeLog(String msg) { ... } }

// 对象适配器（推荐）
class OldLoggerAdapter implements Logger {
    private OldLogger old = new OldLogger();
    public void log(String msg, Level level) {
        old.writeLog("[" + level + "] " + msg);  // 转换调用
    }
}
// Spring 体现：HandlerAdapter（适配不同 Controller 类型到统一 handle 方法）

2. 装饰器模式 Decorator

意图：动态地给对象添加额外职责，比继承更灵活（运行时叠加，继承是编译时）。

// Java IO 的经典装饰器
InputStream in = new FileInputStream("file.txt");
in = new BufferedInputStream(in);    // 添加缓冲功能
in = new GZIPInputStream(in);        // 添加解压功能
// 可以任意叠加，顺序有意义

// 自定义：为 Service 添加日志和事务
interface OrderService { Order create(OrderDTO dto); }
class OrderServiceImpl implements OrderService { ... }  // 核心实现

class LogDecorator implements OrderService {
    private OrderService delegate;
    LogDecorator(OrderService s) { this.delegate = s; }
    public Order create(OrderDTO dto) {
        log.info("create order: {}", dto);
        Order o = delegate.create(dto);
        log.info("order created: {}", o.getId());
        return o;
    }
}
💡 装饰器 vs 代理：装饰器增强功能（对客户端透明，知道被装饰的对象）；代理控制访问（对客户端隐藏实际对象）。Spring AOP 本质是动态代理，而非装饰器。

3. 代理模式 Proxy

意图：为对象提供代理以控制访问。三种代理：保护代理（权限）、虚拟代理（懒加载）、远程代理（RPC）。

// 静态代理（编译时确定）
class UserServiceProxy implements UserService {
    private UserService real;
    UserServiceProxy(UserService s) { this.real = s; }
    public User getUser(Long id) {
        if (!hasPermission()) throw new AccessDeniedException();
        return real.getUser(id);
    }
}

// JDK 动态代理（见泛型反射章节）
// CGLIB 代理（见 Spring AOP 章节）

// Spring @Transactional 就是代理模式的应用：
// TransactionInterceptor 代理目标方法，开/提交/回滚事务
代理类型应用场景Spring 体现
保护代理权限控制Spring Security 方法级安全
虚拟代理懒加载，按需创建Hibernate 延迟加载
远程代理RPC 调用Dubbo Consumer Stub
缓存代理缓存结果@Cacheable（Spring Cache）

4. 门面模式 Facade

意图：为子系统提供统一入口，简化客户端与复杂子系统的交互。降低耦合，不限制对子系统的直接访问。

// 下单场景（调用多个子系统）
class OrderFacade {
    private InventoryService inventory;
    private PaymentService payment;
    private NotificationService notification;
    private LogisticsService logistics;

    // 统一入口
    public OrderResult placeOrder(OrderRequest req) {
        inventory.reserve(req.getItems());  // 库存预留
        PayResult pay = payment.pay(req.getPayInfo()); // 支付
        logistics.createShipment(pay.getOrderId());    // 创建物流
        notification.send(req.getUserId(), "下单成功"); // 通知
        return OrderResult.success(pay.getOrderId());
    }
}
// 客户端只需调用 OrderFacade.placeOrder()，不需要了解子系统细节

Spring 体现：JdbcTemplate（JDBC 门面），RestTemplate（HTTP 门面），SLF4J（日志门面）

5. 桥接模式 Bridge

意图：将抽象与实现解耦，使两者可以独立变化。用组合代替多层继承。

// 问题：Shape + Color 两个维度变化，继承会爆炸
// 不好：RedCircle, BlueCircle, RedSquare, BlueSquare...

// 桥接：抽象层持有实现层引用
interface Color { String fill(); }
class Red implements Color { public String fill() { return "红色"; } }
class Blue implements Color { public String fill() { return "蓝色"; } }

abstract class Shape {
    protected Color color;  // 桥接点
    Shape(Color c) { this.color = c; }
    abstract String draw();
}
class Circle extends Shape {
    Circle(Color c) { super(c); }
    public String draw() { return color.fill() + "圆形"; }
}
// 扩展 Shape 或 Color 互不影响
Circle c = new Circle(new Red());  // "红色圆形"

6. 组合模式 Composite

意图：将对象组织成树形结构，使单个对象和组合对象的使用一致（统一接口）。

// 文件系统（文件 + 目录统一处理）
interface FileComponent {
    void display(String indent);
    long getSize();
}
class File implements FileComponent {
    private String name; private long size;
    public void display(String i) { System.out.println(i + name); }
    public long getSize() { return size; }
}
class Directory implements FileComponent {
    private String name;
    private List<FileComponent> children = new ArrayList<>();
    public void add(FileComponent c) { children.add(c); }
    public void display(String i) {
        System.out.println(i + name + "/");
        children.forEach(c -> c.display(i + "  "));
    }
    public long getSize() { return children.stream().mapToLong(FileComponent::getSize).sum(); }
}
// Spring 体现：CompositePropertySource、CompositeMessageSource

7. 享元模式 Flyweight

意图：共享大量细粒度对象，减少内存开销。区分内部状态（共享）和外部状态（不共享）。

// Integer 缓存（JDK 内置享元）
Integer a = 127; Integer b = 127;
System.out.println(a == b);  // true（-128~127 缓存）
Integer c = 128; Integer d = 128;
System.out.println(c == d);  // false（超出缓存范围，新建对象）

// 字符串常量池也是享元
String s1 = "hello"; String s2 = "hello";
System.out.println(s1 == s2);  // true

// 数据库连接池（享元）：复用 Connection 对象
// 线程池：复用 Thread 对象
// Spring 中：单例 Bean 就是享元模式
模式关键特征Java/Spring 典型应用
适配器接口转换HandlerAdapter, InputStreamReader
装饰器功能叠加（同接口包装）BufferedInputStream, FilterWriter
代理访问控制（相同接口）Spring AOP, Dubbo Consumer Stub
门面简化接口JdbcTemplate, RestTemplate, SLF4J
桥接解耦抽象与实现JDBC Driver（DriverManager+Driver）
组合树形结构统一处理文件系统, UI组件树, XML DOM
享元共享细粒度对象Integer缓存, 字符串池, 连接池
