01MP 是什么
MyBatis 的增强版，不替换 MyBatis

MyBatis-Plus（MP）在 MyBatis 的基础上做了功能增强，不改变 MyBatis 的任何行为。已有的 XML Mapper 和注解照常工作，MP 只是在旁边加了一层开箱即用的 CRUD 能力。

内置 CRUD
BaseMapper 提供 18 个通用方法，selectById / insert / updateById / deleteById 等，不用写 SQL 也能完成基本操作
条件构造器
QueryWrapper / LambdaQueryWrapper 链式 API 拼接 WHERE 条件，类型安全，无硬编码字段名
分页插件
MybatisPlusInterceptor 内置物理分页，自动改写 SQL + 执行 COUNT，适配 MySQL / PostgreSQL / Oracle 等主流数据库
功能扩展
自动填充（createTime / updateTime）、逻辑删除（is_deleted）、乐观锁（version）、代码生成器，覆盖 80% 的重复工作
MP 的核心设计原则：只做增强，不做改变。引入 MP 后，原有的 XML Mapper 一行都不用改。
02三层核心接口
BaseMapper / IService / ServiceImpl 分工

MP 提供三层接口，越往上封装越高，使用越方便，但也越不灵活。

层次接口 / 类定位代表方法
Mapper 层BaseMapper<T>直接操作数据库，18 个通用方法insert / deleteById / selectById / selectList / selectPage
Service 层IService<T>封装业务逻辑，批量操作等saveBatch / updateBatchById / listByIds / page / lambdaQuery
Service 实现ServiceImpl<M,T>实现 IService，注入 BaseMapper继承即可，无需重复实现
// Mapper 接口只需继承 BaseMapper，MP 自动注入 18 个方法
public interface UserMapper extends BaseMapper<User> {
    // 也可以按需添加自定义 XML 方法
}

// Service 接口
public interface UserService extends IService<User> {}

// ServiceImpl 声明两个泛型：Mapper 类型 + 实体类型
@Service
public class UserServiceImpl extends ServiceImpl<UserMapper, User>
        implements UserService {}
saveBatch 底层默认用循环单条 INSERT，不是真正的批量 SQL。若要真正的批量插入（一条 SQL 多个 VALUES），需用 XML 写 foreach，或开启 JDBC rewriteBatchedStatements=true。
03条件构造器
QueryWrapper vs LambdaQueryWrapper

条件构造器用于拼接 WHERE 条件，替代手写 SQL 字符串。两种风格：

AbstractWrapper
→
QueryWrapper（字符串列名）
+
LambdaQueryWrapper（Lambda 列名）
// QueryWrapper：列名用字符串，有硬编码风险
QueryWrapper<User> qw = new QueryWrapper<>();
qw.eq("name", "张三").ge("age", 18).orderByDesc("create_time");
List<User> list = userMapper.selectList(qw);

// LambdaQueryWrapper：列名用 Lambda，重构字段名时不会遗漏（推荐）
LambdaQueryWrapper<User> lqw = new LambdaQueryWrapper<>();
lqw.eq(User::getName, "张三")
   .ge(User::getAge, 18)
   .orderByDesc(User::getCreateTime);
List<User> list = userMapper.selectList(lqw);
方法对应 SQL说明
eq / ne= / !=等于 / 不等于
gt / ge / lt / le> / >= / < / <=大于 / 大于等于 / 小于 / 小于等于
like / likeLeft / likeRightLIKE %val% / %val / val%模糊查询
in / notInIN (...) / NOT IN (...)集合匹配
isNull / isNotNullIS NULL / IS NOT NULL空值判断
betweenBETWEEN a AND b范围查询
orderByAsc / orderByDescORDER BY col ASC/DESC排序
selectSELECT col1, col2指定查询列（避免 SELECT *）
UpdateWrapper — 只更新指定列
// 只把 age >= 18 的用户 status 改为 1，不更新其他字段
UpdateWrapper<User> uw = new UpdateWrapper<>();
uw.ge("age", 18).set("status", 1);
userMapper.update(null, uw); // 第一个参数为 null 表示实体字段不参与更新
条件构造器里的 condition 参数（三参数重载）可以控制某个条件是否加入：eq(name != null, "name", name)，只有 name 非空时才加 eq 条件，替代 MyBatis 的 <if> 标签。
04分页插件
MybatisPlusInterceptor + PaginationInnerInterceptor

MP 3.x 的新插件体系是 MybatisPlusInterceptor（外层容器）+ 各种 InnerInterceptor（功能单元）。分页功能由 PaginationInnerInterceptor 实现。

// Spring Boot 配置
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mpInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 指定数据库类型，分页 SQL 方言不同
        interceptor.addInnerInterceptor(
            new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
// 使用分页：第 2 页，每页 10 条
Page<User> page = new Page<>(2, 10);
LambdaQueryWrapper<User> lqw = new LambdaQueryWrapper<>()
        .ge(User::getAge, 18);
Page<User> result = userMapper.selectPage(page, lqw);

System.out.println("总条数：" + result.getTotal());
System.out.println("总页数：" + result.getPages());
List<User> records = result.getRecords();
  • SQL 改写拦截 Executor.query()，用 JSqlParser 解析原 SQL，改写成 SELECT ... LIMIT ?, ?，同时生成 SELECT COUNT(*) FROM (...) 查询总条数
  • COUNT 优化若原 SQL 有 ORDER BY，COUNT 查询会自动去掉（ORDER BY 不影响条数但会降低 COUNT 性能）；若原 SQL 用了 GROUP BY，COUNT 包一层 SELECT COUNT(*) FROM (原SQL)
  • 关闭 COUNTnew Page<>(1, 10, false) 第三个参数传 false，不查总条数，节省一次 COUNT SQL
05自动填充
MetaObjectHandler — 创建时间 / 更新时间自动写入

自动填充解决的是每次 insert/update 都要手动设置 createTime、updateTime 的重复问题。两步配置：标注字段 + 实现处理器。

// Step 1: 实体类字段加注解
@TableField(fill = FieldFill.INSERT)           // 只在 INSERT 时填充
private LocalDateTime createTime;

@TableField(fill = FieldFill.INSERT_UPDATE)    // INSERT 和 UPDATE 都填充
private LocalDateTime updateTime;

@TableField(fill = FieldFill.INSERT)
private Long createBy;                         // 创建人（结合 Security 上下文获取）
// Step 2: 实现 MetaObjectHandler
@Component
public class MyMetaHandler implements MetaObjectHandler {
    @Override
    public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createTime",
            LocalDateTime.class, LocalDateTime.now());
        this.strictInsertFill(metaObject, "updateTime",
            LocalDateTime.class, LocalDateTime.now());
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updateTime",
            LocalDateTime.class, LocalDateTime.now());
    }
}
自动填充只在通过 MP 的 insert() / updateById() 方法操作时生效。直接用 XML 写的 SQL、或者用 UpdateWrapper 写的 SET 语句，不会触发自动填充。
06逻辑删除 & 乐观锁
@TableLogic — 逻辑删除

逻辑删除不是真正删数据，而是把 is_deleted（或 deleted）字段从 0 改成 1。后续查询自动过滤掉已删除的数据。

// 实体类
@TableLogic(value = "0", delval = "1")  // value=未删除值，delval=已删除值
private Integer deleted;
// 也可以全局配置，不用每个实体都写
  • 删除行为调用 deleteById() 实际执行 UPDATE user SET deleted=1 WHERE id=?
  • 查询行为所有通过 BaseMapper / IService 的查询自动追加 AND deleted=0 条件
  • 注意唯一索引字段（如手机号）逻辑删除后仍占用唯一值，重新注册同手机号会失败。解法：唯一索引改成联合索引 (phone, deleted)，或删除时把 phone 改写成随机值
@Version — 乐观锁

乐观锁用于解决并发更新时的数据覆盖问题。核心思路：读取时带上 version，更新时检查 version 是否还和读取时一致，不一致说明被其他人改过，更新失败。

@Version
private Integer version;  // 数据库里初始值为 0

更新时 MP 自动把 SQL 改写成：

UPDATE user SET name=?, version=version+1
WHERE id=? AND version=?  -- version 必须等于读取时的值
  • 失败处理SQL 影响行数为 0 时说明版本不匹配（已被其他线程更新），业务层需捕获并重试或提示用户刷新重试
  • 适用场景读多写少、冲突概率低的场景。商品库存扣减这种高并发场景冲突率高，重试成本大，用 Redis + 原子操作或数据库悲观锁（SELECT ... FOR UPDATE）更合适
07代码生成器
AutoGenerator — 根据数据库表生成完整代码

代码生成器读取数据库表结构，自动生成 Entity / Mapper / Mapper XML / Service / ServiceImpl / Controller，省去手写重复模板。

FastAutoGenerator.create("jdbc:mysql://...", "root", "password")
    .globalConfig(builder -> builder
        .author("yourname")
        .outputDir(System.getProperty("user.dir") + "/src/main/java"))
    .packageConfig(builder -> builder
        .parent("com.example")
        .entity("entity")
        .mapper("mapper")
        .service("service"))
    .strategyConfig(builder -> builder
        .addInclude("user", "order")     // 只生成这两张表
        .entityBuilder()
            .enableLombok()              // 生成 @Data
            .enableTableFieldAnnotation()
        .mapperBuilder()
            .enableMapperAnnotation()
        .serviceBuilder()
            .formatServiceFileName("%sService"))
    .execute();
代码生成器适合项目初始化阶段批量生成骨架，生成后需要手动调整业务逻辑。不建议在已有业务逻辑的项目上重复执行（会覆盖已有修改）。
08多租户 & 动态表名
TenantLineInnerInterceptor — 自动追加租户条件

SaaS 多租户场景下，每张表都有 tenant_id 字段，每个查询都要带上 WHERE tenant_id = ?。用 TenantLineInnerInterceptor 可以让 MP 自动追加，不用每次手写。

interceptor.addInnerInterceptor(new TenantLineInnerInterceptor(
    new TenantLineHandler() {
        @Override
        public Expression getTenantId() {
            // 从当前线程上下文（ThreadLocal / SecurityContext）取租户 ID
            Long tenantId = TenantContext.getCurrentTenantId();
            return new LongValue(tenantId);
        }

        @Override
        public String getTenantIdColumn() {
            return "tenant_id";  // 租户列名
        }

        @Override
        public boolean ignoreTable(String tableName) {
            // 不需要租户隔离的表（如字典表）返回 true
            return "sys_dict".equals(tableName);
        }
    }
));
  • SQL 改写SELECT 自动追加 AND tenant_id = ?；INSERT 自动填充 tenant_id；UPDATE / DELETE 也追加
  • 超级管理员若需要查所有租户数据，在 getTenantId() 里判断是否是管理员，是则返回 null（MP 不追加条件）
DynamicTableNameInnerInterceptor — 动态表名

按年月分表（如 order_2024_01）时，同一个 Mapper 需要操作不同表名。DynamicTableNameInnerInterceptor 在 SQL 执行前把固定表名替换成动态表名。

interceptor.addInnerInterceptor(new DynamicTableNameInnerInterceptor() {{
    setTableNameHandler((sql, tableName) -> {
        if ("order".equals(tableName)) {
            // 根据当前时间决定查哪张表
            String suffix = LocalDate.now().format(
                DateTimeFormatter.ofPattern("yyyy_MM"));
            return tableName + "_" + suffix; // order_2024_01
        }
        return tableName;
    });
}});
多个 InnerInterceptor 同时使用时，注意注册顺序：分页插件要放在动态表名 / 多租户插件之后，因为分页 SQL 是在最终表名确定后才执行 COUNT 改写的。
