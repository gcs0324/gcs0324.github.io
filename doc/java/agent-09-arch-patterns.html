01Agent 核心概念
什么是 AI Agent

AI Agent（智能体）是一个能够自主感知环境、做出决策、调用工具、执行动作的系统。它不是一次性回答问题，而是围绕一个目标，反复进行"思考→行动→观察结果"的循环，直到任务完成。

  • 核心组成：LLM（大脑）+ Tools（手脚）+ Memory（记忆）+ Planning（规划能力）
  • 本质区别：普通 LLM 调用是"一问一答"，Agent 是"给一个目标，自己拆解步骤去完成"
  • 典型例子：用户说"帮我查一下今天的天气然后发到钉钉"，Agent 会自主调用天气 API → 拼接消息 → 调用钉钉 API，而不是需要用户分步指令
  • 决策方式：每一步都由 LLM 根据当前上下文决定下一步做什么，不是预定义的固定流程
Agent 与 Chain 的区别
维度Chain（链）Agent（智能体）
执行流程预定义的固定步骤序列（A → B → C）动态决策，每一步由 LLM 决定下一步做什么
工具调用固定顺序调用，流程编译时确定运行时根据需要选择调用哪个工具
循环能力不支持循环，线性执行支持循环，可以反复尝试直到成功
适用场景流程确定、步骤固定的任务（如 RAG 检索增强生成）需要动态决策、多步骤探索的任务（如自动化运维、复杂查询）
复杂度简单可控，容易调试复杂度高，行为不完全可预测
成本LLM 调用次数固定，成本可控每步决策都调 LLM，成本与任务复杂度正相关
面试要点：Chain 是"编排好的流水线"，Agent 是"有自主判断力的工人"。面试时用这个比喻能快速说清楚两者区别。
02ReAct 模式
ReAct: Reasoning + Acting

ReAct 是目前最主流的 Agent 架构模式，核心思想是将推理（Reasoning）和行动（Acting）交织进行。LLM 先思考当前该做什么（Thought），然后执行一个动作（Action），观察执行结果（Observation），再基于结果继续推理，如此循环。

①
Thought（思考）
LLM 分析当前状态，决定下一步应该做什么。例如："用户要查订单，我需要先调用订单查询接口"
②
Action（行动）
选择并调用一个工具，传入参数。例如：调用 orderService.query(orderId="12345")
③
Observation（观察）
获取工具返回的结果。例如：订单状态为"已发货"，物流单号为 SF123456789
循环判断
如果已经获得足够信息，输出最终答案；否则回到①继续推理
为什么 ReAct 效果好：它让 LLM 的推理过程"可见"。每一步的 Thought 都是对当前状态的总结，相当于给了 LLM 一个"工作记忆"，避免在多步推理中迷失方向。
ReAct 实现细节
  • Prompt 模板：通常在 System Prompt 中给出 Thought/Action/Observation 的格式示例，让 LLM 按固定格式输出，便于解析
  • 工具选择：每次 Action 只调用一个工具。LLM 从可用工具列表中选择最合适的，输出工具名和参数的 JSON
  • 终止条件：当 LLM 输出"Final Answer"而非 Action 时，循环结束。也可以设置最大循环次数（通常 5-10 次）防止无限循环
  • 上下文管理：每轮循环的历史（Thought+Action+Observation）都拼接到对话历史中，LLM 能看到完整的决策链
  • 常见问题：如果工具返回错误信息，LLM 需要在下一轮 Thought 中分析原因并换一种方式尝试
ReAct 的局限：每步都调 LLM，5 轮循环就是 5 次 LLM 请求。对于复杂任务（10+ 步），延迟和成本都较高。此时可以考虑 Plan-and-Execute 模式。
03Plan-and-Execute
先规划后执行

Plan-and-Execute 将任务分为两个阶段：规划阶段由一个 LLM 生成完整的执行计划（步骤列表），执行阶段逐步执行每个步骤。适合步骤较多、流程相对可预测的任务。

①
Planner（规划器）
接收用户目标，输出一个有序步骤列表。例如：1.查询用户信息 → 2.查询订单列表 → 3.查询物流状态 → 4.汇总生成报告
②
Executor（执行器）
按顺序执行每个步骤，每步调用相应的工具。执行器不需要重新规划，只负责执行
③
Re-Planner（可选：重新规划）
执行完所有步骤后，如果结果不满足要求，或者中间发现计划需要调整，可以触发重新规划

与 ReAct 的核心区别：ReAct 是"边想边做"，每一步都重新决策；Plan-and-Execute 是"先想好再做"，规划和执行分离。

适用场景：需要 5 步以上的复杂任务、可以并行执行多个步骤的场景、流程相对标准化的工作流（如数据处理管道）。
04Reflexion
反思与自我纠错

Reflexion 是一种让 Agent 从失败中学习的模式。当 Agent 的执行结果不符合预期时，它会对自己的行为进行反思（Reflection），分析失败原因，将经验存入记忆，然后在下一次尝试中避免同样的错误。

①
执行任务
Agent 按常规流程（如 ReAct）执行任务，得到一个结果
②
评估结果
用评估器（可以是另一个 LLM 调用）判断结果是否满足目标。例如：代码测试是否通过、答案是否正确
③
反思分析
如果结果不合格，LLM 分析失败原因。例如："查询条件写错了，应该用 userId 而不是 orderId"
④
存入记忆
将反思结论存入长期记忆，在下一次尝试时作为上下文提供给 LLM
重新尝试
带着之前的经验重新执行任务，通常 2-3 次尝试内就能成功
面试要点：Reflexion 的核心价值是让 Agent 具备"从错误中学习"的能力。典型应用：代码生成 Agent 反复运行测试用例直到全部通过，每轮根据失败的测试反馈调整代码。
05Agent Loop 实现
Agent Loop 核心循环

Agent Loop 是所有 Agent 架构模式的底层机制——一个无限循环，直到任务完成或达到终止条件。无论 ReAct 还是 Plan-and-Execute，底层都是这个循环。

①
接收输入
接收用户目标和当前上下文（包括历史对话、工具返回结果）
②
LLM 推理
将完整上下文发送给 LLM，获取下一步动作（工具调用指令或最终回答）
③
解析输出
解析 LLM 的响应：如果是工具调用，提取工具名和参数；如果是最终回答，结束循环
④
执行工具
调用对应的工具函数，获取返回结果
⑤
更新上下文
将本轮的 Action 和 Observation 追加到对话历史中
终止检查
检查是否达到终止条件（最终回答 / 最大循环次数 / 用户中断），否则回到②
// 伪代码：Agent Loop 核心实现
while (true) {
    Response resp = llm.chat(messages);        // ② LLM 推理
    if (resp.isFinalAnswer()) return resp;     // 终止：输出最终答案
    ToolCall call = parseToolCall(resp);        // ③ 解析工具调用
    String result = tools.execute(call);        // ④ 执行工具
    messages.add(assistantMessage(resp));       // ⑤ 更新上下文
    messages.add(toolMessage(result));
    if (loopCount++ > MAX_LOOPS) break;        // 防止无限循环
}
最大循环次数：生产环境建议设置为 5-10 次。超过这个次数通常意味着 LLM 无法解决问题，需要人工介入。设置太小可能任务未完成就被截断。
06模式对比与选型
各模式适用场景对比
模式核心思想适用场景LLM 调用次数典型延迟
ReAct边思考边行动，逐步推进简单到中等复杂度任务、需要动态决策与步骤数相同每步 1-3 秒
Plan-and-Execute先规划完整计划，再逐步执行步骤多、流程可预测、可并行的任务规划 1 次 + 执行 N 次规划较慢，执行较快
Reflexion从失败中反思学习，反复尝试允许试错的任务、代码生成、复杂推理尝试次数 × 每次步骤数多次尝试，总延迟较高
Multi-Agent多个 Agent 分工协作需要专业分工的复杂系统、团队模拟各 Agent 独立调用取决于协作模式
选型建议：大多数场景从 ReAct 开始，它最通用也最容易实现。当任务步骤超过 5 步且流程可预测时，考虑 Plan-and-Execute。当任务需要高准确率且允许重试时，加入 Reflexion。
