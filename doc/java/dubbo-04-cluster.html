1. 集群容错策略

策略类名行为适用
Failover（默认）FailoverCluster失败自动重试其他 Provider，retries=2读操作，幂等写操作
FailfastFailfastCluster失败立即抛异常，不重试非幂等写操作（下单）
FailsafeFailsafeCluster失败忽略，返回空结果日志记录等非关键操作
FailbackFailbackCluster失败后异步定时重试消息通知、最终一致性
ForkingForkingCluster并行调用多个 Provider，最快返回实时性要求高，资源充足
BroadcastBroadcastCluster广播调用所有 Provider，任一失败报错缓存刷新、配置更新
⚠️ Failover 重试会加大 Provider 压力，非幂等操作（如创建订单）必须用 Failfast，防止重复数据！
// 配置容错策略
@Reference(cluster = "failfast", retries = 0)
OrderService orderService;

@Reference(cluster = "failover", retries = 2)
QueryService queryService;

2. 超时与重试

超时机制

  • Consumer 侧超时：timeout 参数（默认 1000ms），超时抛 TimeoutException
  • Provider 侧超时：TimeoutFilter 检测，执行超时打印警告日志（但不中断执行）
  • 超时≠取消：Provider 继续执行，只是 Consumer 放弃等待，可能导致重复执行

重试配置

@Reference(
    timeout = 2000,     // 单次调用超时 2s
    retries = 2         // 失败重试 2 次（共 3 次）
)
// 总耗时可能：3 * 2000 = 6s（最坏情况）

// 方法级超时（更细粒度）
@Reference(methods = {
    @Method(name = "queryUser", timeout = 500, retries = 0),   // 不重试
    @Method(name = "listUsers", timeout = 3000, retries = 1)
})
⚠️ 设置重试时，确保接口是幂等的！Failover 重试会换一台 Provider，重试前已执行的操作不会回滚。

3. 服务降级

当 Provider 不可用或响应慢时，返回兜底数据，保证 Consumer 基本可用。

方式说明
force:return null直接返回 null，不发起远程调用（Consumer 侧，紧急屏蔽）
fail:return null调用失败后返回 null（不抛异常）
mock=true调用失败执行 Mock 类（接口名 + Mock 后缀）
mock=com.x.MockImpl调用失败执行指定 Mock 实现
// Mock 降级实现
public class UserServiceMock implements UserService {
    @Override
    public User getUser(Long id) {
        // 返回兜底数据，如缓存数据或默认对象
        return User.builder().id(id).name("Unknown").build();
    }
}

// 配置
@Reference(mock = "true")  // 自动查找 UserServiceMock
@Reference(mock = "return null")  // 直接返回 null

4. 限流与熔断

Dubbo 内置限流

  • executes：Provider 并发执行数限制（超出抛 ExecuteLimitedException）
  • actives：Consumer 侧并发调用数限制（超出等待或抛异常）
  • accepts：Provider 接收的最大连接数
  • connections：Consumer 到每个 Provider 的最大连接数
@Service(executes = 100)     // 最多 100 个并发执行
@Reference(actives = 50)      // Consumer 最多 50 个并发调用

Sentinel 集成（推荐）

Dubbo 官方推荐 Sentinel 实现熔断降级，通过 SPI 自动集成 Dubbo Filter。

Sentinel 规则说明
流量控制（FlowRule）QPS/并发数限制，支持预热、排队模式
熔断降级（DegradeRule）基于错误率/慢调用比例/异常数自动熔断
热点限流（ParamFlowRule）对某个参数值限流（如某个商品 ID）
系统保护（SystemRule）基于 CPU/Load/RT 的全局保护

5. 异步调用

// 方式1：异步 + Future（JDK CompletableFuture，Dubbo 2.7+）
@Reference(async = true)
UserService userService;

userService.getUser(1L);  // 立即返回 null
CompletableFuture<User> future = RpcContext.getContext().getCompletableFuture();
future.thenAccept(user -> System.out.println(user.getName()));

// 方式2：接口直接返回 CompletableFuture（推荐）
public interface UserService {
    CompletableFuture<User> getUser(Long id);
}

// Provider 实现
@Override
public CompletableFuture<User> getUser(Long id) {
    return CompletableFuture.supplyAsync(() -> userDao.findById(id));
}

6. 泛化调用

Consumer 无需引入 Provider 接口 jar，直接通过接口名 + 方法名 + 参数发起调用。适合网关、测试工具等场景。

// 泛化调用
ReferenceConfig<GenericService> ref = new ReferenceConfig<>();
ref.setInterface("com.example.UserService");
ref.setGeneric("true");

GenericService genericService = ref.get();
Object result = genericService.$invoke(
    "getUser",                        // 方法名
    new String[]{"java.lang.Long"},   // 参数类型
    new Object[]{1L}                  // 参数值
);

// 结果是 Map，key 为字段名
Map<String, Object> user = (Map) result;
System.out.println(user.get("name"));

7. 版本与分组

概念用途配置
version（版本）接口升级兼容，灰度发布@Service(version="2.0") / @Reference(version="2.0")
group（分组）同一接口不同实现，AB测试@Service(group="a") / @Reference(group="b")
version="*"Consumer 随机调用任意版本灰度期间混流
// 蓝绿部署（版本）
@Service(version = "1.0")  // 旧版 Provider
@Service(version = "2.0")  // 新版 Provider

@Reference(version = "2.0")  // 新版 Consumer
@Reference(version = "*")    // 随机选择（金丝雀）

// AB测试（分组）
@Service(group = "groupA", weight = 80)   // 80% 流量
@Service(group = "groupB", weight = 20)   // 20% 流量
