## 一、Headroom 是什么？

Headroom 是一个 **本地优先的 AI Agent 上下文压缩层**（Apache 2.0 开源），由 Netflix 高级工程师 **Tejas Chopra** 于 2026 年 1 月开源。它像一个"内容清洁工"——插在 Claude Code / Codex / Cursor 等 AI Agent 与 LLM 提供商之间，在请求发送给模型之前，对工具输出、日志、代码搜索结果、RAG 片段、对话历史等进行智能压缩。

核心理念：**同样的答案，只花一小部分的 token。**

## 三、核心压缩能力

### 3.1 四层压缩管道

```
你的 Agent（Claude Code）
    │
    ▼
┌──────────────────────────────────────────┐
│  Headroom（本地运行，数据不出机器）         │
│                                          │
│  CacheAligner → ContentRouter → 压缩器   │
│                  ├─ SmartCrusher (JSON)   │
│                  ├─ CodeCompressor (AST)  │
│                  └─ Kompress-base (文本)  │
└──────────────────────────────────────────┘
    │
    ▼
LLM 提供商（Anthropic / OpenAI / Bedrock）
```

| 组件 | 目标 | 技术 |
|------|------|------|
| **CacheAligner** | 稳定 prompt 前缀，提高 KV 缓存命中率 | 不变/可变内容分离 |
| **ContentRouter** | 自动识别内容类型并路由到最优压缩器 | 规则 + ML 混合 |
| **SmartCrusher** | JSON/结构化数据压缩 | 去重 key、列式重整 |
| **CodeCompressor** | AST 感知代码精简 | tree-sitter 解析器 |
| **Kompress-base** | 自然语言/日志压缩 | HuggingFace 模型（本地） |
| **RTK** | Shell 命令输出过滤 | 内置于 Headroom |

### 3.2 CCR（可逆压缩）

这是 Headroom 区别于其他方案最关键的设计：
- 压缩时原始数据存在本地 LRU 缓存中，不删除
- LLM 可以通过 `headroom_retrieve` 工具按需取回原始内容
- 实际使用中模型几乎不需要检索，因为智能压缩已经保留了关键内容
- 1ms 内即可取回原始数据

## 五、如何接入 Claude Code

### 最简方式（推荐）

```bash
# 1. 安装
pip install "headroom-ai[all]"

# 2. 一行命令包裹 Claude Code
headroom wrap claude

# 3. 同时开启跨 Agent 记忆
headroom wrap claude --memory
```

执行后 Headroom 自动启动代理服务器，Claude Code 的所有 API 请求会先经过压缩再发送给 Anthropic。

### 代理模式（零代码改动）

```bash
headroom proxy --port 8787
# 然后正常使用 Claude Code，设置 ANTHROPIC_BASE_URL=http://localhost:8787
```

### 验证效果

```bash
headroom perf        # 模拟实际负载，查看压缩率
headroom stats       # 查看实时压缩统计
```

### 查看储蓄

```bash
headroom stats
# 输出类似：
# ┌─────────────────────┬──────────┬──────────┬────────┐
# │ Session             │ Original │ Compressed│ Savings│
```

## 七、风险与注意事项

### 7.1 已知 Bug（截至 2026-07-03）

| 严重度 | 问题 | 影响 |
|--------|------|------|
| **P1** | Python 进程 **SIGILL 崩溃**（Illegal instruction） | 部分环境下库模式直接挂 |
| **P1** | 代理模式下长多轮编码任务压缩率仅 **0.3%** | 某些场景基本无效 |
| **P1** | Claude Code v2.1.196+ **禁用 Remote Control** 当使用自定义 ANTHROPIC_BASE_URL | Headroom 代理下 Remote Control 不可用 |
| **P2** | 代理静默卡死（/livez 无响应） | 需手动重启 |
| **P2** | 503 上游错误于 streaming + anthropic-beta header | 特定条件下请求失败 |
| **P2** | Dashboard 节省金额始终显示 $0 | 不影响功能但报告不准 |
| **P3** | RTK 路径未加入 PATH 导致 "command not found" | 安装后需手动配置 |

### 7.2 技术风险

1. **项目仍在快速迭代**：v0.29，正在进行大规模"Realignment"重构（退役 ~25K LOC），API 可能不稳定
2. **tree-sitter 依赖重**：CodeCompressor 需要编译原生模块，CI 环境可能有问题
3. **CCR 缓存占内存**：长时间会话可能涨到几百 MB
4. **代码浏览场景压缩率低**：仅 47%，复杂场景可能触发额外 retrieve 调用反而更慢
5. **首次启动慢**：Kompress-base 模型下载 + 冷启动大上下文可达 200-300s（有 30s 预算超时保护）

### 7.3 设计哲学保护

Headroom 采用 **fail-open 设计**：压缩失败时请求照常转发，不会丢数据，最多损失节省而非正确性。这是个重要的安全网。

### 结论

**值得安装。**

对于中度以上使用 Claude Code 的用户，Headroom 的投入产出比极高——安装只需一行 `pip install`，接入只需 `headroom wrap claude`，Fail-open 设计保证了最坏情况只是省不了钱而不会丢数据。

核心价值排序：
1. **省钱**（最直接）：60-92% token 节省
2. **延长会话**（最实用）：30 分钟 → 3 小时+
3. **省心**（最省事）：零代码改动，wrap 即用
4. **生态红利**（最有潜力）：跨 Agent 记忆、MCP 集成、自动学习失败模式

```bash
# 第一步：先跑性能测试看你的场景能省多少
```
