🐙 Section 2: GitHub 高价值项目

anthropics/skills

⭐ 170,036 · Python · 官方 Agent Skills 发布仓库

项目定位：Agent Skills 的规范与示例集，定义「技能 = 文档 + 资产 + 触发条件」的结构化封装。

核心设计：把可复用的 agent 能力做成自包含目录（SKILL.md + 资源文件），按任务类型组织，agent 按需加载。核心创新是把「提示词片段」提升为「可管理、可版本化、可审计的资产」。

同类对比：vs 纯提示词库——多了结构、版本与触发机制；vs MCP——MCP 管工具接入、Skills 管知识/流程封装，二者互补而非竞争。

学习价值 9/10 · 推荐指数 9/10 · ✅ 立即关注

TencentCloud/TencentDB-Agent-Memory

⭐ 22,661 · TypeScript · 团队级 Agent 记忆中枢

项目定位：把对话、文档、代码转成 agent 团队可复用的记忆资产。

核心设计：记忆作为独立数据层（hub）而非模型缓存，强调跨 agent、跨会话的组织级沉淀。代表「记忆即基础设施」路线。

同类对比：vs 本地向量库——面向组织共享与权限；vs ai-memory——后者从 CLI/handoff 个人场景切入，前者重心在团队协作。

学习价值 8/10 · 推荐指数 8/10 · ✅ 立即关注

vitali87/code-graph-rag

⭐ 4,548 · Python · Monorepo 代码知识图谱 RAG

项目定位：解决 agent 对大型代码库「检索不到、理解不深」的问题。

核心设计：代码解析成符号图 + 图结构检索，比纯向量更懂调用关系与跨文件依赖。

同类对比：vs 纯 RAG（如 langchain 向量检索）——增加图谱维度处理多语言 monorepo；与 Claude 生态的 CodeGraph 同思路，是自建检索增强的极佳学习范本。

学习价值 8/10 · 推荐指数 8/10 · ✅ 立即关注

usestrix/strix

⭐ 54,276 · Python · AI 渗透测试 Agent

项目定位：用 agent 自动化发现与修复漏洞的开放工具。

核心设计：把渗透流程拆成 agent 任务链（侦察→扫描→利用验证→报告），配套工具调用与人工确认环节。是「agent 长周期任务编排」的工程样本。

同类对比：vs 传统扫描器（nuclei 等）——多了自主规划与上下文理解；vs 安全 skill 库（Anthropic-Cybersecurity-Skills）——一个偏任务执行、一个偏知识资产。

学习价值 7/10 · 推荐指数 7/10 · ✅ 立即关注

semantica-agi/semantica

⭐ 8,618 · Python · 图原生上下文基础设施

项目定位：「Graph-Native Infrastructure for Context and Accountable AI」——把上下文做成图结构，支持可审计的 AI 系统。

核心设计：上下文去中心化的图存储 + 溯源/责任链，面向企业级对 AI 行为可解释的需求。与 agent 记忆方向互补：记忆解决「记住」，它解决「记得住且可追溯到为什么」。

同类对比：vs 传统向量记忆——强调关系与可审计性；与 code-graph-rag 共享图增强思路，但对象从代码扩展到通用上下文。

🧪 Section 6: 实验项目推荐

1. 打造个人/团队 Agent Skills 库

周末可做：把你日常 agent 工作流中重复的流程（code review、依赖排查、文档生成）写成 3-5 个 skill，用 anthropics/skills 规范组织，接入 Claude Code 或 Codex 实测效果。

2. 给自己的项目搭代码检索增强

用 code-graph-rag 思路对自己的一个私人 repo 做符号图 + 向量检索，让 agent 回答「改 X 会影响谁」前先查图。工作量 1-2 天，落地即用。

3. 搭建本地推理参考栈

用 llmfit 在现有硬件上选出可跑的最优模型，再用 omlx 起一个 Apple Silicon 推理服务，Benchmark 一下与云端的成本/延迟差——直接体验「端侧 + 云端混合」的工程形态。
